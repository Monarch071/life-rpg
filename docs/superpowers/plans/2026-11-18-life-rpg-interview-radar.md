# Life RPG — большая анкета с ИИ, диаграмма характеристик, новый вид героя. План

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:**
- **Большая анкета.** 50–100 вопросов: характер и тип личности, телосложение и вес, здоровье, режим, ум, деньги и доход, отношения, цели, стресс. ИИ, если настроен, задаёт уточняющие вопросы и пишет портрет героя с полной статистикой. Персонаж строится по этой анкете, и ИИ выдаёт задания с опорой на портрет.
- **Диаграмма характеристик.** Семиугольная «паутинка» на 7 осей. Поверх неё — полупрозрачный контур «неделю назад», чтобы был виден рост.
- **Новый вид героя без фото.** Вместо простого рисованного человечка — стильный тёмный аниме‑силуэт с подсветкой и призыв «Создай героя по фото». Настоящий образ по‑прежнему делает ИИ по фото (этап 4).

**Решения пользователя:** аватар — через ИИ по фото; анкету ведёт ИИ поверх базового набора вопросов, без ключа работает только базовый набор; осей 7.

## Global Constraints

- Весь текст — на русском, стиль как в редизайне: токены `src/styles.css`, `StatIcon`/`STAT_COLORS`, `LevelBadge`, 3D‑кнопки, карточки. Кнопки ≥ 44 px, `role="status"`/`role="alert"`.
- Без ключа ИИ всё работает: базовые вопросы плюс расчёт характеристик по правилам.
- Ответ ИИ — недоверенные данные. Всё валидируется. Характеристики анкеты — целые 1–20.
- Уровень и характеристики никогда не падают. Анкета может поднять стартовые характеристики, но не опустить: берём поэлементный максимум, как у `onboarding_completed`.
- Чувствительные ответы (вес, деньги, здоровье) хранятся в журнале событий: на устройстве и на собственном сервере пользователя. Провайдеру ИИ они уходят только для анализа и уточняющих вопросов. Перед отправкой — явная строка: «Ответы будут отправлены в <провайдер> для анализа». Ключ ИИ — как раньше, только на устройстве.
- Черновик незавершённой анкеты хранится локально под ключом `interviewDraft` и сохраняется после каждого ответа. Его надо добавить в `isLocal` в `src/backup.ts`, если ключ не попадает под существующие префиксы.
- Никаких новых зависимостей. Диаграмма — чистый SVG.
- `npx vitest run` и `npm run build` зелёные после каждой задачи.

### Task 1: Семиугольная диаграмма характеристик и новый силуэт героя

export function radarPoints(values: number[], max: number, r: number, cx: number, cy: number): [number, number][]  // ось i под углом −90° + i·360/n; значение ограничивается 0..max

Диаграмма `StatRadar`:

- Анимация появления: полигон растёт из центра (`transform: scale` от 0 до 1, 500 мс), выключена при `prefers-reduced-motion`.
- `role="img"`, `aria-label` перечисляет «Сила 14, …».
- Ширина 100%, максимум 340 px.

Размещение — вкладка «Герой», карточка сразу под бейджем уровня: заголовок «Характеристики», переключатель «Диаграмма / Список». По умолчанию диаграмма, существующий список остаётся как второй вид.

Новый вид героя без фото — `Avatar`, когда нет `image`:
- Вместо детального рисованного человека — стилизованный тёмный аниме‑силуэт в полный рост: динамичная поза, развевающийся плащ, острые пряди волос.

- Тень = тот же силуэт фиолетовый, как сейчас.

На «Главной» и во вкладке «Герой» при отсутствии образа ИИ — компактная плашка‑призыв «Создай героя по своему фото» с кнопкой, ведущей к блоку «Аватар от ИИ» (или к настройкам ИИ, если ключа нет). ### Task 2: Банк вопросов и подсчёт характеристик по правилам

**Files:** Create `src/domain/interview.ts`, `src/domain/interview.test.ts`. Modify `src/domain/types.ts`, `src/domain/replay.ts`, `src/domain/replay.test.ts`.

**Interfaces:**
```ts
export type QKind = 'choice' | 'multi' | 'scale' | 'number' | 'text'
export interface Question { id: string; section: SectionId; kind: QKind; text: string; options?: string[]; min?: number; max?: number; unit?: string; optional?: boolean }
export type SectionId = 'personality' | 'body' | 'health' | 'routine' | 'mind' | 'money' | 'social' | 'goals' | 'spirit'
export const SECTIONS: { id: SectionId; title: string; icon: string }[]   // icon — имя lucide-иконки
export const QUESTIONS: Question[]   // 70–80 вопросов
export type Answers = Record<string, string | number | string[]>
export function ruleStats(a: Answers): Record<Stat, number>   // 1..20 каждая
export function validAnswer(q: Question, v: unknown): boolean
```

Состав `QUESTIONS` (тексты пишет исполнитель, по‑русски, коротко и по‑человечески):

| Раздел | Вопросов | Что спрашиваем |
|---|---|---|
| `personality` | ~15 | 10 утверждений по «Большой пятёрке», шкала 1–5 от «совсем не про меня» до «точно про меня»; интроверт/экстраверт; реакция на стресс; что мотивирует: соревнование, признание, деньги, свобода, мастерство |
| `body` | ~9 | рост в см, вес в кг, желаемый вес, телосложение (выбор), отжимания/подтягивания/планка (числа), сколько км пробежит, шаги в день |
| `health` | ~7 | сон в часах, качество сна 1–5, курение, алкоголь, вода, энергия по времени суток, хронические ограничения (текст, необязательно) |
| `routine` | ~8 | подъём и отбой, часы работы, свободное время в будни и выходные, сколько часов в играх, экранное время, где теряешь время (multi) |
| `mind` | ~7 | образование, сколько читаешь, чему хочешь научиться, языки, концентрация 1–5, сколько учишься в неделю |
| `money` | ~9 | доход в месяц, сбережения, долги, ведёшь ли учёт, траты на импульсивные покупки, финансовая цель и срок, подушка в месяцах, источники дохода (multi) |
| `social` | ~7 | друзья и круг общения, отношения, страх выступлений 1–5, конфликтность, помощь другим, нетворкинг |
| `goals` | ~7 | главная цель на год (текст), три навыка мечты, что бросить, «идеальный день через год» (текст), что раньше мешало |
| `spirit` | ~6 | стресс 1–5, медитация, благодарность, смысл/ценности (multi), удовлетворённость жизнью 1–5 |

`ruleStats` — прозрачные веса:
- Сила — отжимания, подтягивания, планка.
- Выносливость — бег, шаги, сон.
- Интеллект — чтение, учёба, концентрация.
- Дисциплина — сознательность из «Большой пятёрки», режим, мало игр и экрана.
- Харизма — экстраверсия, страх выступлений (обратно), круг общения.
- Финансы — подушка, учёт, долги (обратно).
- Дух — стресс (обратно), удовлетворённость, практики.

Результат нормируется в 1–20, честно низкие значения — это нормально. Нечисловые или пропущенные ответы → нейтральное значение.

Событие и `replay`:
```ts
| { type: 'interview_completed'; answers: Answers; followups: { q: string; a: string }[]; analysis: Analysis | null }
interface Analysis { archetype: string; summary: string; strengths: string[]; weaknesses: string[]; stats: Record<Stat, number>; focus: string[]; questGuidance: string }
```
- В `replay` стартовые характеристики = поэлементный максимум из всех анкет: `onboarding_completed` даёт `initialStats`, а `interview_completed` даёт `analysis?.stats` после валидации (иначе `ruleStats(answers)`).
- Валидация `analysis`: строки обрезаются (`archetype` ≤ 40, `summary` ≤ 1200, элементы массивов ≤ 120, не больше 6 элементов), `stats` — целые 1–20 через `isStat`. Невалидный `analysis` → `ruleStats`.
- `GameState.character: { archetype: string; summary: string; strengths: string[]; weaknesses: string[]; focus: string[]; questGuidance: string; date: ISODate } | null` — по последнему валидному `interview_completed`. Без анализа ИИ: `archetype` = текущий класс, остальное пусто.
- `GameState.interviewAnswers: Answers | null` — последние ответы, нужны для промпта заданий.
- Повреждённые ответы не валят `replay`: `answers` — объект, значения — строки, числа или массивы строк. Остальное отбрасывается.

- [ ] Тесты:
  - id вопросов уникальны;
  - вопросов от 60 до 100, в каждом разделе есть хотя бы один;
  - `validAnswer` для каждого типа;
  - `ruleStats`: сильный атлет → Сила ≥ 14, сидячий → Сила ≤ 6, все значения в 1..20, пустые ответы → всё в 1..20 без исключений;
  - `replay` поднимает характеристику через анкету, но не опускает;
  - невалидный `analysis` (`stats.str = 99`) → используется `ruleStats`;
  - `character` заполняется.
- [ ] Коммит `feat(game): deep interview question bank, rule-based stats, interview event`.

### Task 3: ИИ‑интервью и задания по портрету

**Files:** Create `src/ai/interview.ts`, `src/ai/interview.test.ts`. Modify `src/ai/tasks.ts` (`questContext` добавляет портрет и ключевые ответы), `src/ai/tasks.test.ts`.

**Interfaces:**
```ts
export async function aiFollowups(cfg: AiConfig, section: SectionId, answers: Answers): Promise<{ id: string; text: string; kind: 'text' | 'scale' | 'choice'; options?: string[] }[]>  // 0–3 уточнения на раздел
export async function aiAnalysis(cfg: AiConfig, answers: Answers, followups: { q: string; a: string }[]): Promise<Analysis>  // валидирует; бросает AiError при мусоре
```

- **Уточнения:** промпт содержит ответы раздела. ИИ просят задать до 3 коротких вопросов, которые помогут понять человека для прокачки. Тон уважительный, без медицинских диагнозов и без давления на тему веса и денег. Ответ ИИ валидируется: текст 5–200 символов, у `choice` 2–6 вариантов.
- **Анализ:**
  - **Промпт.** Все ответы и уточнения, 7 характеристик с определениями и шкала 1–20 с примерами («5 — новичок, 10 — средний взрослый, 15 — заметно выше среднего, 20 — топ»). Просьба быть честным: не завышать и не занижать.
  - **Что вернуть.** `archetype` — аниме‑класс/архетип по‑русски, например «Тихий стратег». `summary` — 4–6 предложений, обращение «ты». Также `strengths`, `weaknesses`, `focus` (3 зоны роста) и `questGuidance` — как давать задания этому человеку: темп, что мотивирует, чего избегать.
  - **Проверка.** Схема и валидация — та же, что в `replay`.
- **Задания по портрету:** `questContext` добавляет блок «Портрет героя»: `archetype`, `summary`, `focus`, `questGuidance`, а также 10–15 самых важных ответов — вес и цель по весу, доход и цель по деньгам, мотивация, ограничения здоровья, игры и экранное время. Системный промпт заданий требует, чтобы каждое задание помогало `focus` или закрывало слабость из портрета.
- [ ] Тесты (с замоканным `generateJson`):
  - `aiFollowups` отбрасывает невалидные вопросы и ограничивает их тремя;
  - `aiAnalysis`: `stats` вне 1..20 → `AiError`; валидный ответ проходит; строки обрезаются;
  - `questContext` с `character` содержит `archetype` и `focus`.

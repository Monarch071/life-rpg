# Life RPG v2 — этап «Ядро». Дизайн

Дата: 2026-11-19. Цель: к 1 декабря 2026 (старт сезона «Зима») перевести игру на механику v2: уровни 1–100, Основа + Форма, 24 навыка, ранги E–S, типы дней, сборка дня по правилам, новая серия, сезоны, золото.

Источники (оба у владельца, в репозиторий не копируются):
- **[S]** «Life RPG — детальная проработка систем» — формулы и числа; при расхождении побеждает он. Ссылки вида [S§6] — номер раздела.
- **[P]** «Life RPG — личная версия» — что остаётся в соло-версии и план этапов. Ссылки [P§3] и т. п.

Решения владельца (обязательны): стек не меняется (GitHub Pages + Cloudflare Worker/D1 + журнал событий); только соло-версия; ежедневная «Тень»-соперник удаляется; работа по этапам [P§8], этот документ — только этап «Ядро».

Репозиторий публичный: личные данные (работа, места, город, доходы, цели-боссы) сюда не попадают. Типы дней по умолчанию — обобщённые времена из таблицы [P§2] с нейтральными подписями.

## 1. Как документы ложатся на текущую архитектуру

| Документ [S§12] | У нас |
|---|---|
| `xp_ledger` — неизменяемый журнал начислений | Журнал событий Dexie/D1 — единственный источник правды. Строки «леджера» **выводятся** в `replay()` из событий и отдаются как `GameState.ledger` |
| `daily_state`, формы, серия | Считаются в `replay()` при «закрытии» каждого прошедшего дня (цикл по датам) |
| `profile_snapshot` | `GameState.start` — из последних валидных `interview_completed` / `onboarding_completed` |
| `day_types / schedule` | Событие `day_types_set` (последнее побеждает), иначе `BALANCE.dayTypes` |
| `tasks` | `quests_issued` (+ `quest_rerolled`, `custom_quest_added`, `day_changed`) |
| `verifications` | Поле `verify`/`photo` в `quest_completed`; авто — по метрикам из `health_packet`/`metric_logged` |
| `seasons / season_progress` | Чистая функция календаря + событие `season_theme_set`; сезонный XP — сумма строк леджера |
| `shop` | `reward_*` события; стартовый набор засевается событиями с детерминированными id |
| «Все числа баланса в одном конфиге» [S§12] | `src/domain/balance.ts` — один объект `BALANCE` |
| Supabase/Vercel, `user_id` | Не нужны: один пользователь, синк через Worker уже есть |

Принципы, которые не меняются: `replay(events, now)` — чистая функция, порядок входа не влияет на результат (сортировка по `(ts, id)`, дубли id отбрасываются), **любое** битое событие игнорируется и никогда не бросает исключение, неизвестные типы игнорируются (совместимость вперёд). Worker типы событий не проверяет — правок Worker для новых событий не нужно.

## 3. События

### 3.1. Новые

```ts
| { type: 'day_types_set'; types: DayType[] }                       // последнее по ts побеждает; невалидные элементы отбрасываются
| { type: 'day_changed'; date: ISODate; dayType: DayType; at: HHMM } // «День изменился»
| { type: 'quest_rerolled'; date: ISODate; questId: string; replacement: Quest }
| { type: 'custom_quest_added'; date: ISODate; quest: Quest }       // kind 'custom'
| { type: 'season_theme_set'; theme: ThemeId }                       // действует с игровой даты события до конца сезона
```

### 3.2. Изменённые (только необязательные поля — старые события валидны)

```ts
| { type: 'day_started'; date; work; wakeAt; dayType?: DayType; energy?: number /* 1–10 */ }
| { type: 'quest_completed'; date; questId; verify?: 'photo'; photo?: string /* имя блоба */ }
| { type: 'reward_created'; rewardId; title; price; effect?: 'streak_freeze' | 'day_off' }
| { type: 'interview_completed'; answers; followups; analysis: Analysis | null }   // Analysis + scores?, startLevel?, levelWhy?, skillLevels?
```

`Quest` получает необязательные поля:

```ts
export type Rank = 'E' | 'D' | 'C' | 'B' | 'A' | 'S'
export type Verify = 'auto' | 'photo' | 'honest'
export type QuestKind = 'daily' | 'challenge' | 'restore' | 'custom'
interface Quest {
  id; date; title; stat; minutes; window; xp; auto; templateId;   // как было; xp — предпросмотр (новые) или итог (легаси)
  difficulty?: 1|2|3|4|5;                      // только легаси
  rank?: Rank; skills?: [SkillId] | [SkillId, SkillId]; kind?: QuestKind; why?: string;
}
```

`Quest.auto.metric` расширяется значением `'workoutMin'`.

### 3.3. Легаси (остаются в union, обрабатываются миграцией — раздел 8)

`skill_unlocked` (игнорируется), недельные `kind: 'shadow_wins'`, `Quest.difficulty`, `ai_tuning.factors` (по-прежнему двигают множители количества).

### 3.4. Валидация (граница доверия)

Каждое новое поле проверяется в replay: `Rank` ∈ RANKS, `SkillId` ∈ каталогу, `DayType` через `validDayType`, `energy` — целое 1–10, `photo` — `/^[a-z0-9-]{1,64}$/`, `theme` ∈ THEMES, `effect` ∈ двух значений, строки обрезаются. Неверное необязательное поле отбрасывается, неверное обязательное — отбрасывает событие.

## 5. Формулы

### 5.1. Уровень [S§1], [P§3]

- `xpToNext(L) = round(100 · L^1.5)`: 3→520, 10→3 162, 20→8 944, 40→25 298, 55→40 789 (в [S§1] те же числа, округлённые до десятков).
- `levelFromXp(total, start)`: уровень начинается со `start`, XP внутри — 0; потолок 100 (на 100 `need = 0`, интерфейс показывает «MAX»).
- В уровень идёт 100% XP всех строк леджера.

### 5.2. Стартовый профиль [S§2], [S§4], [P§3]

- **Оценка сферы** 0–100 на характеристику. Источник по приоритету: `analysis.scores` (ИИ) → `analysis.stats` 1–20 старого формата → `ruleStats(answers)` → `initialStats(profile)`; значения 1–20 переводятся `scoreFrom20(v) = round((v − 1) / 19 · 100)`. При нескольких анкетах берётся поэлементный максимум (как сейчас).
- **Стартовая Основа** = `min(70, round(5 + 0,65 · оценка))`: 0→5, 40→31, 50→38, 100→70.
- **Стартовый уровень:** ИИ — `analysis.startLevel` (целое 1–60, вне диапазона — поле отбрасывается) с объяснением по каждой сфере `levelWhy`. **Правила (моё решение):** `clamp(round(среднее семи оценок / 2), 1, 50)`; объяснение по сфере — «Оценка N/100 по ответам раздела …». Нет ни анкеты, ни онбординга — 1.
- **Стартовые уровни навыков:** ИИ — `analysis.skillLevels` по таблице [S§4] (не занимался 1, <6 мес 2, 6–12 мес 3, 1–3 года 4–5, 3+ лет 6, профессия 7; >7 не ставится). **Правила (моё решение, максимум 4):** из имеющихся ответов анкеты:

| Навык | Ответ → уровень |
|---|---|
| Силовые | отжимания ≥40 → 4, ≥20 → 3, ≥10 → 2 |
| Кардио | бег ≥10 км → 4, ≥5 → 3, ≥2 → 2 |
| Сон | сон 7–9 ч и режим ≥4 → 3 |
| Чтение | книг в месяц ≥4 → 4, ≥2 → 3, ≥1 → 2 |
| Языки | ответ про языки не пуст → 2 |
| Технологии | учёба ≥5 ч/нед → 3, ≥2 → 2 |
| Режим | стабильность 5 → 4, 4 → 3 |
| Фокус | концентрация 5 → 4, 4 → 3 |
| Общение | широкий круг → 3, несколько человек → 2 |
| Выступления | страх выступлений 1 → 4, 2 → 3 |
| Бюджет | учёт регулярно → 4, иногда → 2 |
| Накопления | подушка ≥6 мес → 4, ≥3 → 3, ≥1 → 2 |
| Заработок | среди источников бизнес/фриланс/инвестиции → 3 |
| Осознанность | медитация регулярно → 4, иногда → 3, пробовал → 2 |
| остальные | 1 |

### 5.3. Формула награды [S§1], [P§3]

```
XP   = round( База_ранга × K_проверки × (1 + min(1, Σбонусов)) × (1 − min(0,5, Σштрафов)) × mult )
Gold = round( 0,2 × XP )
```

- База: E 20, D 40, C 70, B 120, A 200, S 350.
- Проверка: авто 1,0 (метрика из «Здоровья» выполнила `auto`-цель), фото 0,9 (`verify: 'photo'`), честное слово 0,7 (ручная галочка). Если по шаблону с `auto` поставили галочку руками, а метрика потом пришла и цель выполнена — засчитывается авто (моё решение).
- `mult` — множитель вне потолков: «Вернуть форму» ×2 [S§2]; иначе 1.
- Бонусы этого этапа: серия `min(0,5; 0,02 × серия)` (серия на начало дня задания), тема сезона +0,2 (характеристика задания в теме, летом — также рабочие навыки), самая слабая характеристика +0,25 (минимальная Основа на начало дня; ничья — по порядку STATS). Класс и перки = 0 до этапа 5.
- Штрафы этого этапа: «Ослабление» −0,2 — три предыдущих дня (не дни отдыха, только после первого дня игры) без единого выполненного задания [S§1]; «Перекос» −0,2 (моё определение) — характеристика задания самая сильная по Основе **и** получила >50% XP характеристик за последние 7 закрытых дней при сумме ≥200 XP. Усталость = 0 до этапа 3 (`fatiguePenalty(f) = 0,003·f` уже в `progression.ts`).
- Пример [S§1] «Зал 45 минут»: C, авто → 70; бонусы 0,2 + 0,1 + 0,1 = 0,4 → 98; штраф 0,06 → **92 XP и 18 золота** (юнит-тест на чистую функцию; в игре класс/перк/усталость появятся позже).
- XP задания считается **в replay при выполнении**; при выдаче в `Quest.xp` пишется предпросмотр по той же функции (проверка: авто, если у шаблона есть `auto`, иначе честное слово).

### 5.4. Куда идёт XP [S§1]

| Куда | Сколько |
|---|---|
| Уровень | 100% |
| Навык | 1 тег — 100%; 2 тега — 60% главному, 40% второму (`round(0,6x)` и остаток) |
| Характеристика | столько же, сколько навык, в характеристику навыка; рабочие навыки — 50/50 Харизма/Дисциплина (`round(x/2)` в Харизму, остаток в Дисциплину) |
| Сезон | 100%, если дата не в Прологе |

Строки леджера: задание, идеальный день (+50), «День изменился» (+20), недельное (150), этап легаси-босса (100 / +200). У последних трёх нет навыка; недельное и босс с характеристикой — 100% в характеристику; идеальный день и смена дня — только уровень, сезон и золото (моё решение).

### 5.5. Основа [S§2], [P§3]

- 1–100, не падает. Очко стоит `50 + 5·S` XP (S — текущее значение). 20→30 = 1 725, 50→60 = 3 225, 1→100 = 29 700.
- `baseFromXp(start, xp) → { value, into, need }`; на 100 `need = 0`.

### 5.6. Форма [S§2], [P§3]

- `Форма = min(1, XP_окна / (дней_окна × норма))`, считается по **закрытым** дням (ночью при закрытии дня [S§2]), окно — последние `min(14, закрытых дней)` дней, дни отдыха выбрасываются.
- Норма = `max(15, 0,7 × средний дневной XP характеристики за прошлые 60 закрытых дней без дней отдыха)`.
- Первые 30 дней от первого дня с заданиями — норма из плана: `max(15, 0,7 × средний предпросмотр XP выданных заданий этой характеристики в день)`.
- Пример [S§2]: среднее 40 → норма 28, нужно 392, набрано 150 → **38%**, статус «Заброшена».
- Статусы: ≥80% «В форме», 40–79% «Проседает», <40% «Заброшена». До первого закрытого дня — `form = null`, статус `new` (считается «в форме»).
- Следствия этого этапа: при «Заброшена» сборка дня даёт обязательное «Вернуть форму» (ранг D, если потолок ≥ D, иначе E; ×2 XP; не чаще раза в 7 дней на характеристику; не больше одного в день). Ослабление перков/класса — этап 5.

### 5.7. Навыки [S§4], [P§3]

- 24 навыка: 21 личный (по 3 на характеристику) + 3 рабочих (Лидерство, Делегирование, Командная работа). Наставничество убрано.
- Уровни 1–10, переход n→n+1 стоит `100·n`; 1→10 = 4 500.
- `lastDate` — дата последнего выполненного задания с тегом; нужна для приоритета и «на грани ржавчины» (≥23 дней без практики, навык хоть раз качался). Сама ржавчина, перки и +50% за снятие ржавчины — этап 5.

Каталог (`id`, название, характеристика):

| STR | END | INT | DIS | CHA | WLT (`fin`) | SPI | Рабочие (`team`) |
|---|---|---|---|---|---|---|---|
| `strength` Силовые | `cardio` Кардио | `reading` Чтение | `routine` Режим | `social` Общение | `budget` Бюджет | `mindfulness` Осознанность | `leadership` Лидерство |
| `mobility` Мобильность | `sleep` Сон | `languages` Языки | `focus` Фокус | `speaking` Выступления | `savings` Накопления | `reflection` Рефлексия | `delegation` Делегирование |
| `sports` Спортивные игры | `nutrition` Питание | `tech` Технологии | `habits` Контроль привычек | `negotiation` Переговоры | `earning` Заработок | `rest` Отдых | `teamwork` Командная работа |

У каждого навыка — подсказка проверки и примеры E/C/A из [S§4] (для рабочих — соло-примеры из [P§3] в обобщённом виде: «провести короткую планёрку», «расписать задачу и проверить результат», «помочь коллеге в завал»).

### 5.8. Ранги [S§6], [P§4]

- `rankCap(level, skillLevel) = min(потолок по уровню, потолок по навыку)`. Уровень: E 1+, D 10+, C 20+, B 35+, A 50+, S 70+. Навык: E/D 1+, C 3+, B 5+, A 7+, S 9+.
- Примеры [S§6]: уровень 55, Силовые 2 → D; Переговоры 8 → A.
- Параметр шаблона на ранге: `round(base × paramScale[rank] × множитель_количества)`; у шаблона может быть свой `scale` и `maxRank` (шаги: E 1 / D 1,25 / C 1,5 / B 2, максимум B). Шаги стартуют с `max(stepsUsual, лучший 7-дневный средний × 1,1)` [S§6].
- Калибровка количества: существующие множители по характеристике (`difficulty.ts`), пороги приведены к [S§6]: ≥85% → ×1,1 за неделю, <60% → ×0,85. Калибровка по каждому шаблону и повышение ранга при +50% — позже (раздел 10).

## 6. День

### 6.1. Типы дней [P§2], [S§6]

```ts
export type DayKind = 'day' | 'evening' | 'off' | 'rest'
export interface DayType { id: string; kind: DayKind; label: string; wake: HHMM | null; busy: { start: HHMM; end: HHMM } | null; bed: HHMM | null; slots: number }
```

По умолчанию (`BALANCE.dayTypes`, редактируются в настройках событием `day_types_set`):

| id | Подпись | Подъём | Занят | Отбой | Слотов | Правило расстановки |
|---|---|---|---|---|---|---|
| `day` | Дневная смена | 08:00 | 10:00–19:00 | 00:00 | 4 | утром и вечером |
| `evening` | Вечерняя смена | 11:00 | 16:00–02:00 | 03:00 | 3 | всё до начала смены |
| `off` | Выходной | 11:00 | — | 01:00 | 5 | весь день |
| `rest` | Отдых / болезнь | — (время нажатия) | — | — | 1 | без давления |

`Profile.workTemplates` больше не используется «Моим днём» (поле остаётся в типе для старых событий).

### 6.2. Закрытие дня [S§6], [P§2]

- День закрывается через час после отбоя по шаблону, но не раньше 00:00 (моё решение: игровая дата не может начаться до полуночи) и не позже 04:00:
  `closeMin(bed) = clamp(m < 720 ? m + 60 : m + 60 − 1440, 0, 240)`, где `m` — минуты отбоя. 00:00→01:00, 01:00→02:00, 03:00→04:00, 05:00→04:00, 23:30→00:30, 22:00→00:00.
- Тип дня `d` — из последнего `day_changed` за `d`, иначе из `day_started` за `d`; день без старта или с `bed = null` закрывается в 04:00.
- Игровая дата: `gameDateAt(ts, closeOf)` — календарная дата `ts`, но если минуты от полуночи `< closeOf(вчера)`, это ещё вчера. Глобальная настройка «час смены дня» (`cutoffHour`) удаляется: из `replay`, `useGame`, `Home`, `Settings`; `backup.ts` продолжает лишь проверять старое поле и вызывает `replay(events, now)`.
- `GameState.today.closesAt` — ts закрытия текущего дня; Главная по нему понимает, что сутки сменились (вместо `gameDate(now(), cutoffHour)`).
- Окно засчёта выполнения (`gameDate(ts, 6) ≤ q.date ≤ gameDate(ts, 0)`) не меняется: оно покрывает закрытия 00:00–04:00.

### 6.3. Energy этого этапа

Пока нет HP/Energy из данных (этап 3), Energy = утренняя оценка 1–10 из «Моего дня» × 10 (`day_started.energy`, необязательна); нет — последняя энергия чек-ина × 10; нет — 50 [P§7: утренняя оценка — ручной ввод].

### 6.4. Сборка дня [S§6], [P§4]

Чистая функция `assembleDay(ctx)`; ИИ потом лишь переписывает `title` и пишет `why`.

1. **Слоты:** `dayType.slots`; Energy < 40 → −1 (минимум 1); Energy ≥ 70 → +1 задание-вызов. Тип `rest` — всегда 1 слот, без вызова.
2. **Обязательные** (в счёт слотов): «Вернуть форму» (5.6); навык на грани ржавчины (не больше одного); при Energy < 40 — одно задание на Дух. Задание на Дух при усталости >50 — этап 3.
3. **Кандидаты:** все шаблоны банка (шаблоны вредных привычек — только для привычек из профиля, навык «Контроль привычек»), ранг — `rankCap(level, уровень главного навыка)`, но не выше `maxRank` шаблона.
4. **Приоритет** `P = 3·босс + 2·(1 − Форма) + 1,5·тема + min(1, дней_без_навыка / 7) − 2·повтор_вчера`. Босс = 1, если у активного (легаси) босса та же характеристика; цепочек нет. Навык ни разу не качался → 7 дней. Форма `null` → 1. Ничьи — сидированный `rng(date)`.
5. **Ограничения:** не больше 2 заданий на характеристику (по главной); характеристика без выданных заданий вчера и позавчера ставится раньше остальных; одинаковый шаблон — один раз.
6. **Ранги:** `всего = слоты (+ вызов)`; на своём потолке `round(0,6 × всего)`; вызов — на ранг выше потолка навыка; остальные — на ранг ниже (E остаётся E). Energy < 40 → без вызова и без физических заданий ранга C и выше.
7. **Расстановка:** свободные окна ≥20 минут; тренировки заканчиваются не позже чем за 2 часа до отбоя; тип `evening` — только окна до начала смены. Остальное — существующий `placeQuests` (по энергии времени суток профиля).
8. **Тексты:** правила дают `why` («форма Силы проседает», «тема сезона», «давно не качал навык», «вернуть форму ×2»); при настроенном ИИ — `aiQuestTexts` переписывает `title`/`why`, не меняя ранг, навыки, XP и окно.

### 6.5. Итог дня и серия [S§6], [P§4]

- День засчитывается в серию, если выполнено ≥60% выданных (без «перенесённых» после смены дня) заданий; ритуалов пока нет (лестницы — этап 4).
- Пропуск (включая день без выданных заданий): серия `floor(серия × 0,5)`.
- Идеальный день (выдано ≥1 и всё выполнено) — строка леджера +50 XP.
- День типа `rest` или купленный «день без заданий» — серия не меняется, день не входит в окна формы; лимит 14 дней отдыха в календарный месяц, сверх — обычный день (заглушка до режима восстановления этапа 3).
- «Заморозка серии» из магазина: ближайший пропуск после покупки не уменьшает серию; не больше 2 покупок в месяц.
- Серия на «сегодня» = серия закрытых дней + (сегодня уже ≥60% ? 1 : 0).

### 6.6. «День изменился» [P§4]

`day_changed { date, dayType, at }`: выполненное остаётся; если у нового типа меньше слотов, невыполненные задания сверх `слоты − выполнено` (последние по порядку выдачи) помечаются `dropped` — без штрафа и вне знаменателя 60%; остальные перерасставляются в окна нового типа (отображение, как сейчас `replanAfterBusy`); новых заданий не добавляется. +20 XP один раз в день (повторные смены — без XP). Закрытие дня пересчитывается по новому отбою.

### 6.7. Переброс [S§6]

`quest_rerolled { date, questId, replacement }`: только сегодняшнее невыполненное, не `restore`/`custom`; замена — тот же ранг, другой шаблон (`rerollCandidate`). Первый переброс дня бесплатно, дальше 50 золота. Платный переброс принимается, если `золото из строк леджера с датой < даты переброса − цены всех reward_purchased с ts раньше − ранее принятые платные перебросы ≥ 50` (моё решение: сегодняшний заработок не учитывается — это разрывает круг «переброс → XP → золото»). Повтор переброса той же исходной `questId` игнорируется.

### 6.8. Свои задания [S§1], [P§4]

`custom_quest_added`: не больше 2 в день (третье игнорируется), ранг ставит ИИ (не выше `rankCap`), без ИИ — на ранг ниже потолка (моё решение). Засчитанный XP своих заданий за день = `min(Σ своих, round(Σ остальных / 3))` — это ровно «не больше 25% XP дня»; урезание распределяется пропорционально по строкам.

## 7. Сезоны, золото, магазин

### 7.1. Календарь [P§6], [S§8]

| Период | Даты | Тема по умолчанию | +20% |
|---|---|---|---|
| Пролог | до 2026-11-30 | — | — |
| Зима | 1 дек – конец фев | Разум и дух | Интеллект, Дух |
| Весна | 1 мар – 31 мая | Тело | Сила, Выносливость |
| Лето | 1 июн – 31 авг | Люди | Харизма + рабочие навыки |
| Осень | 1 сен – 30 ноя | Деньги и дисциплина | Финансы, Дисциплина |

`seasonOf(date)` для любого года после Пролога; id вида `winter-2026` (зима 2026/27). Тема меняется в настройках (`season_theme_set`) и действует с игровой даты события до конца текущего сезона; следующий сезон стартует со своей темой.

### 7.2. Сезонный XP

`season.xp` = сумма XP строк леджера с датой в текущем сезоне (Пролог — 0: «XP идёт в уровень, но не в сезон»). `season.step = min(30, floor(xp / 600))`. Награды пути (50 золота за ступень, вещи, фон, рамка, образ, титул) и уменьшенная цена ступени при позднем входе — этап 5; сейчас только полоска «Ступень N/30».

### 7.3. Золото

`gold = Σ gold строк леджера + 25 × достижения − покупки − платные перебросы`. Поле `GameState.currency` переименовывается в `gold`, «Монеты» в интерфейсе — «Золото». Обычные покупки проверяются как сейчас (весь заработок − потраченное ≥ цена).

### 7.4. Покупки с эффектом

Награды с `effect` (`streak_freeze`, `day_off`) меняют правила игры, поэтому проверяются в цикле дней тем же правилом, что платный переброс (6.7), и не перепроверяются в конце.

### 7.5. Недельные

Остаются (полная переработка недели — этап 5). XP фиксированный 150 (множители больше не влияют на XP). Генератор больше не выдаёт `shadow_wins`; без данных о шагах третий тип — `stat_quests` по первой характеристике темы сезона (в Прологе — вторая по слабости).

### 7.6. Стартовый набор магазина [P§6]

Засевается событиями `reward_created` с детерминированными `rewardId: 'default:<slug>'` при запуске, если такого id в журнале ещё нет (повторный посев с другого устройства — дубль id, replay берёт первый; удалённые не возвращаются, потому что их `reward_created` уже есть).

| slug | Название | Цена | effect |
|---|---|---|---|
| `episode` | Серия аниме или сериала | 50 | |
| `games` | Вечер игр без чувства вины | 150 | |
| `match` | Посмотреть матч в спорт-баре | 200 | |
| `cheatmeal` | Читмил | 200 | |
| `freeze` | Заморозка серии (не больше 2 в месяц) | 300 | `streak_freeze` |
| `book` | Новая книга | 400 | |
| `dayoff` | День без заданий, серия не ломается | 600 | `day_off` |
| `treat` | Покупка для себя (свой лимит) | 1000 | |

Предметы для аватара (100–800) — этап 5 (инвентаря нет).

## 11. Мои решения (заполненные пробелы)

1. Стартовый уровень по правилам: `clamp(round(среднее оценок / 2), 1, 50)`; ИИ-уровень принимается в 1–60.
2. Старые оценки 1–20 → 0–100: `round((v − 1) / 19 · 100)`.
3. Стартовые уровни навыков по правилам — по таблице 5.2, максимум 4 (ИИ — до 7 по [S§4]).
4. Легаси-задания: XP как сохранено, ранг по `legacyRank`, навык по карте шаблонов; проверка к ним не применяется.
5. Золото = 20% всех строк, включая легаси; бонус Тени и достижения Тени удаляются.
6. Идеальный день и смена дня дают XP только в уровень/сезон/золото, без навыка и характеристики.
7. XP задания считается в replay при выполнении; бонусы — по снимку на начало игрового дня.
8. Перекос: самая сильная Основа и >50% XP характеристик за 7 закрытых дней при ≥200 XP.
9. Ослабление: три предыдущих не-отдыхающих дня без выполненных заданий, только после первого игрового дня.
10. Закрытие дня не раньше 00:00; день без старта закрывается в 04:00.
11. Тип «Отдых / болезнь» и «день без заданий» замораживают серию и не входят в окна формы, ≤14 в месяц (до режима восстановления).
12. «День изменился»: +20 XP один раз в день; срезаются последние по выдаче невыполненные; новых заданий не добавляется.
13. Energy этапа: утренняя оценка 1–10 ×10 → энергия чек-ина ×10 → 50.
14. Смесь рангов: свой ранг `round(0,6 × всего)`, вызов — только слот Energy ≥70, остальные на ранг ниже.
15. Масштаб параметра шаблона по рангу `E1 D2 C3,5 B6 A10 S16`, с переопределением и `maxRank` на шаблоне.
16. «Вернуть форму»: D, если потолок позволяет, иначе E; ×2 вне потолков бонусов.

## 2. Архитектура

- Журнал — единственный источник правды; `replay(events, now)` чистая, не бросает, порядок входа не влияет. Новые события валидируются полями, неверное отбрасывается.
- Новые чистые модули без знания о журнале: `src/domain/finance.ts` (категории, правила, суммы периода, вердикты лимитов), `src/domain/csvImport.ts` (разбор CSV, ключи строк, дубли с Wallet), `src/domain/rival.ts` (призрак, индекс роста, рекорды, итоги месяца), `src/domain/advanced.ts` (каталог продвинутых классов, испытание), `src/domain/card.ts` (модель карточки и раскладка в операции рисования). Рисование на `<canvas>` — `src/ui/cardCanvas.ts`.
- **Монотонность.** Вердикт недели (призрак, бюджет недели, рекорды недели) — при закрытии воскресенья; месяца (индекс, бюджет месяца, накопления, рекорд накоплений) — при закрытии последнего дня месяца; дня (рекорды дня) — при закрытии дня. В вердикт идут только события, принятые до закрытия (`ts < closesAt`), как данные дня (Автоматика). Поздний импорт выписки меняет аналитику, но не принятые награды **(моё решение)**.
- **Без пересчёта прошлого.** `BALANCE.rivalSince` — игровая дата выхода этапа (ставится в коммите релиза). Раньше неё нет наград призрака, рекордов, бюджетных проверок и продвинутых классов. Значения рекордов и индекс считаются по всей истории — награда только за побитый после `rivalSince` рекорд.
- **Приватность финансов.** Всё финансовое — в журнале на устройстве и на своём Worker (как остальные события). В ИИ не уходит ничего: ни суммы, ни категории, ни магазины, ни заметки, ни строки выписки, ни факт бюджетной проверки. Белый список `masterReport.ts` не расширяется; новые входы ИИ (разбор сезона) строятся отдельным белым списком (§9) и тестом на отсутствие финансовых полей. CSV разбирается на устройстве, файл никуда не отправляется — в журнал попадают только нормализованные строки.
- Числа — в `BALANCE` (§12).

## 3. Призрак [P§5]

### 3.1. Кривая

- **XP дня** `x(d)` — сумма XP строк леджера с датой d (все источники).
- **Призрачный день:** `g(d) = x(тот же день месяца в прошлом месяце)`; если такого дня нет (31 марта → в феврале 28 дней) — `0`: призрак стоит на месте, дублей нет **(моё решение)**.
- **Месячный счёт:** `you(d) = Σ x(k)` и `ghost(d) = Σ g(k)` по дням месяца с 1-го до d включительно. Разница `lead = you − ghost`: «Ты впереди призрака на 340 XP» / «отстаёшь на 120 XP» / «вровень».
- **Когда есть призрак:** у даты d призрак есть, если прошлый календарный месяц целиком внутри сезона (не Пролог) [P§5 «в Прологе призрака ещё нет, первый появится в январе»]. Владелец: декабрь — без призрака, январь — призрак декабря.
- **Сезонный призрак** **(моё решение о показе):** со второго сезона на листе «Сезон» — метка «призрак» на дорожке: сезонный XP прошлого сезона к тому же номеру дня сезона. Наград не даёт.

### 3.2. Обгон недели

- При закрытии воскресенья d ≥ `rivalSince`: если у **всех** 7 дней недели есть призрак и `Σ x > Σ g` по дням недели — строка `source: 'ghost'`, id `ghost:<weekStart>`, `+50 XP` без характеристики (как `flatRow` со `stat = null`) [P§5]. Неделя на стыке месяцев сравнивает каждый день со своим прошлым месяцем.
- Первая возможная награда владельца — неделя 4–10 января (неделя 28 дек — 3 янв частично без призрака).

### 3.3. Состояние

```ts
ghost: { available: boolean; you: number; ghost: number; lead: number; week: { you: number; ghost: number } | null;
         weeksWon: number; season: { step: number; xp: number } | null }
```

## 4. Индекс роста [P§5], [S§11]

- Месяц M, **рабочие дни** — закрытые дни месяца без отдыха, восстановления и купленных дней без заданий (замороженные, как в ранге недели) [P§5 «дни восстановления исключаются из обоих месяцев»].
- **XP/день** = Σ `x(d)` по рабочим дням ÷ их число. Нормировка на день — **(моё решение)**: иначе месяц с днями восстановления и короткий февраль проигрывают сами по себе.
- **Индекс** = `round(100 × XP/день(M) / XP/день(M−1))`.
- **База 150 XP/день** [P§5, S§11], если у M−1 меньше 14 рабочих дней (первый месяц, Пролог, месяц почти целиком в восстановлении) **(моё решение о пороге)**. Владелец: декабрь сравнивается с базой (ноябрь — неполный Пролог).
- Рабочих дней M ноль — индекса нет (`null`).
- Текущий месяц — предварительный индекс по закрытым дням; итог — при закрытии последнего дня месяца.

```ts
growth: { current: { month: string; index: number | null; xpPerDay: number; days: number; base: 'prev' | 'base' };
          months: { month: string; index: number | null; xpPerDay: number; days: number }[] }   // закрытые месяцы, по убыванию, до 24
```

## 5. Зал славы [P§5]

| Рекорд | Значение | Когда решается | Источник |
|---|---|---|---|
| `streak` — самая длинная серия | серия на конец дня | закрытие дня | `history.streak` |
| `steps_day` — максимум шагов за день | шаги дня (правдоподобные: без флага `too_many_steps`, ≤ `plausible.stepsMax`) | закрытие дня | данные дня |
| `week_xp` — лучшая неделя по XP | Σ `x(d)` недели | закрытие воскресенья | леджер |
| `pages_week` — страниц за неделю | Σ `readPages` дней недели, день ≤ 500 страниц | закрытие воскресенья | ручной ввод |
| `focus_day` — минут фокуса за день | `focusMin` дня (режим + таймер), ≤ 960 | закрытие дня | данные дня |
| `savings_month` — месяц с наибольшими накоплениями | «отложено» месяца (§7.5), > 0 | закрытие месяца | финансы |

- **Новый рекорд** — значение строго больше прошлого лучшего, а прошлый лучший **существует и > 0** (первое значение — «рекорд установлен», без награды, иначе первый день дал бы 600 XP) **(моё решение)**.
- **Награда** — `+100 XP` [P§5], строка `source: 'record'`, id `record:<id>:<date>` (не больше одной на рекорд в день), без характеристики; дата ≥ `rivalSince`. Чемпион — ещё +100 (§8.3).
- **Серия** — награда один раз за серию: когда текущая серия впервые обошла прошлый рекорд; дальше рекорд растёт молча до обрыва серии **(моё решение — иначе +100 каждый день)**.
- Анимация — тот же `Celebration` с текстом «Новый рекорд: 14 230 шагов» (показано — `localStorage`).

```ts
records: { id: RecordId; title: string; value: number | null; date: ISODate | null; prev: number | null; unit: string }[]
```

## 6. Карточка «до и после» [P§5], [S§8]

- **Когда:** с 1-го по 7-е число Главная показывает «Твоя карточка за <месяц>» (если в прошлом месяце был хоть один закрытый день с заданиями); в «Анализе» — список месяцев. Критерий этапа — карточка за декабрь 1 января.
- **Модель** `monthCard(state, month)`: месяц; аватар «сейчас» (конец месяца) и «месяц назад» (конец прошлого месяца); уровень на обе даты (из леджера и `startLevel`); индекс роста месяца; «лучший рекорд» — рекорд, побитый в этом месяце с наибольшим относительным приростом, иначе лучший по дате; три характеристики с наибольшим приростом Основы; серия; ступень сезона.
- **История аватара:** `avatarHistory: { date: ISODate; tier: 1|2|3|4; blob: string }[]` — каждое принятое `avatar_image` по `ts`. Аватар на дату — последняя картинка с датой ≤ даты; нет картинки — SVG-аватар по `avatar_updated` на ту дату (тот же `Avatar`, отрисованный в изображение). Одинаковые картинки — карточка всё равно сравнивает уровни и цифры.
- **Рисование:** `cardOps(model, size)` → список операций (`rect`, `text`, `image`, `bar`) — чистая раскладка 1080 × 1920 в «стеклянной ночи» (тёмный фон, свечение, две колонки «было/стало», крупный индекс). `renderCard(ops, images)` выполняет их на `<canvas>` → PNG `Blob`. Шрифт — системный.
- **Сохранить/поделиться:** `saveFile(blob, name)` (обобщение `saveBackup`: share-sheet с файлом → «Сохранить изображение» или сторис; иначе скачивание). Никакой загрузки на сервер.
- **Карточка сезона** — тот же генератор с моделью `seasonCard` (§9).
- На карточке нет финансовых сумм (её выкладывают в сторис): «лучший рекорд» `savings_month` показывается как «Рекорд накоплений» без суммы **(моё решение)**.

## 7. Финансы [P§2], [P§7], [S§4 Бюджет/Накопления/Заработок]

### 7.1. События

```ts
type FinKind = 'expense' | 'income' | 'saving'
| { type: 'fin_category_set'; categoryId: string; title: string; kind: FinKind; limit: number | null; archived?: boolean }
| { type: 'fin_entry_added'; entryId: string; date: ISODate; kind: FinKind; amount: number; categoryId: string; note?: string }
| { type: 'fin_entry_edited'; entryId: string; categoryId?: string; amount?: number; date?: ISODate; removed?: boolean }
| { type: 'fin_rule_set'; ruleId: string; pattern: string; categoryId: string | null }      // null — удалить правило
| { type: 'fin_imported'; importId: string; rows: ImportRow[] }                              // ≤ 1000 строк на событие
| { type: 'fin_import_removed'; importId: string }
interface ImportRow { key: string; date: ISODate; amount: number; text: string }             // amount < 0 — списание, > 0 — поступление
```

Граница доверия: `amount` конечное, `0 < |amount| ≤ 1e8`, два знака; `note`/`text` ≤ 60 символов без управляющих; `title` 1–30; `pattern` 2–40; id ≤ 64; неизвестная категория у записи → «Прочее» своего вида; `fin_entry_edited` к Wallet-записи — по id `wallet:<eventId>`, к строке импорта — `import:<importId>:<key>`. Последнее по `ts` побеждает.

### 7.2. Категории

- Умолчания (id `default:<slug>`, обобщённые): расходы — Продукты, Кафе и доставка, Транспорт, Дом и связь, Здоровье, Одежда, Развлечения, Подписки, Подарки, Прочее; доходы — Зарплата, Подработка, Прочий доход; отложено — Копилка. Своих — до 40.
- `limit` — месячный лимит категории расходов (`null` — без лимита). **Лимит месяца M** — последнее значение, принятое до начала M; категория без лимита до M, получившая первый лимит в M, — первое значение в M **(моё решение: середину месяца нельзя «спасти» поднятием лимита; первый лимит работает сразу)**.
- Архивная категория скрыта в вводе, записи остаются.

### 7.3. Записи

- **Ручные** — `fin_entry_added` (лист «Трата / доход / отложить» из Быстрого ввода: сумма, категория-чипы, дата сегодня или вчера, заметка). Поле «Траты» в Быстром вводе заменяется этим листом; старые `metric_logged spend` остаются графиком и входят в финансы как записи «Прочее» с `source: 'legacy'`.
- **Wallet** — каждый `signal_logged` вида `wallet` (Автоматика): `amount > 0` — трата, `< 0` — возврат (уменьшает категорию); id `wallet:<eventId>`; дата — игровая дата сигнала. Название магазина берётся из события только на устройстве (сейчас `signalOf` его выбрасывает — добавляется поле `merchant` в финансовый вход, `DayData` не меняется).
- **Категория Wallet/импорта:** явная правка `fin_entry_edited.categoryId` → иначе правило: нормализованный текст (нижний регистр, `ё→е`, пробелы схлопнуты) содержит `pattern`; несколько — самый длинный шаблон, ничья — позднее по `ts` → иначе «Без категории» (считается в «Прочее», счётчик на экране «разобрать N»).
- При правке категории Wallet/импорта — галочка «Запомнить для „<магазин>“» → `fin_rule_set` (шаблон — текст магазина, его можно сократить).
- **Авто-засчёт «Записать траты»:** новая `AutoMetric` `finEntries` — число записей расходов дня (ручные + Wallet + импорт, принятые до закрытия дня). Шаблон `expenses` (Бюджет E [S§4]) получает `auto: ≥ n` — засчёт без галочки.

### 7.4. Лимиты и бюджетные проверки [S§4 «неделя в лимите», «месяц в лимите по всем категориям»]

- **Потрачено** категорией за период — Σ расходов (возвраты вычитаются, не ниже 0), без дублей импорта (§7.6).
- **Лимит недели** категории = Σ по дням недели `лимит месяца дня / дней в месяце` (неделя на стыке месяцев честна к обоим) **(моё решение)**.
- **Учёт активен** в периоде, если дней с записью расхода ≥ 3 из 7 (неделя) / ≥ 15 (месяц) — иначе «в лимите» без учёта засчитывалось бы само **(моё решение)**.
- **Неделя в лимите** — новый вид недельного задания `budget_week` (`target 1`, XP недельного, характеристика `fin`): выдаётся, если на понедельник есть хоть один лимит; заменяет третье недельное (шаги или вторая характеристика) **(моё решение: недельных остаётся 3 [S§6 «2–3»])**. Выполнено при закрытии воскресенья, если учёт активен и все категории с лимитом ≤ лимита недели.
- **Месяц в лимите** — при закрытии последнего дня месяца M ≥ `rivalSince`: учёт активен, есть ≥ 1 лимит, все категории с лимитом ≤ лимита → строка `source: 'budget'`, id `budget:month:<M>`, XP ранга A (200) × проверка `honest` 0,7 → **140 XP**, навык Бюджет **(моё решение: ручные данные — честное слово; с ≥ 50% суммы из Wallet/импорта — `auto` 1,0 → 200)**.
- **Отложить 10% дохода** (Накопления C) — при закрытии месяца: доход > 0 и отложено ≥ 10% дохода → `budget:save:<M>`, XP ранга C (70) × 0,7 = **49**, навык Накопления.
- Бюджетные строки — как строки заданий: навык 100% в Бюджет/Накопления, характеристика Финансы, без бонусов и штрафов.

### 7.5. Накопления

- «Отложено» месяца = Σ записей вида `saving` (перевод в копилку; отрицательная сумма — снятие). Не «доход − расход»: остаток на карте не равен накоплениям **(моё решение)**.
- Рекорд зала славы `savings_month` — лучший месяц по «отложено».

### 7.6. Импорт выписки (CSV)

- Только на устройстве: `<input type="file" accept=".csv,text/csv">` → `File.text()` → разбор → предпросмотр → `fin_imported`. Файл не сохраняется и не отправляется; в журнал попадают дата, сумма и описание ≤ 60 символов.
- **Разбор** `parseCsv(text)`: BOM, разделитель `;` / `,` / табуляция (по первой непустой строке — тот, что даёт больше одинаковых колонок), кавычки с `""`, переводы строк внутри кавычек, CRLF. До 5 000 строк, файл ≤ 2 МБ.
- **Колонки** `guessColumns(header)`: дата, сумма (или пара «списание/поступление»), описание — по словарю заголовков (дата/date, сумма/amount, списание/расход/debit, поступление/приход/credit, описание/назначение/детали/description). Не угадано — пользователь выбирает в листе; выбор хранится в настройке `csvMapping` (по набору заголовков).
- **Дата:** `дд.мм.гггг`, `дд.мм.гг`, `гггг-мм-дд`, `дд/мм/гггг`, с временем после пробела. **Сумма:** пробелы и неразрывные пробелы — разряды, запятая или точка — дробь (последний разделитель с 1–2 цифрами после него), знак валюты и код отбрасываются, `−`/`-`/скобки — минус. Строка без даты или суммы — пропуск с причиной в предпросмотре.
- **Ключ строки** `key = hash(date|amount|text|n)`, где n — номер повтора такой же тройки в файле: повторный импорт того же файла не создаёт дублей; две одинаковые покупки в один день остаются двумя.
- **Дубли с Wallet** (в `replay`, независимо от порядка прихода): строка-списание импорта — дубль, если есть ещё не сопоставленная Wallet-трата с той же суммой (до копейки) и датой ±1 день; сопоставление жадное по дате, затем по `ts`. Дубль скрыт из сумм и помечен в списке. Строки из прошлых импортов с тем же `key` — тоже дубль.
- Поступления импорта → `income` «Прочий доход», списания → `expense` по правилам; переводы в копилку пользователь переносит в «Отложено» правкой (или правилом).
- Удалить импорт целиком — `fin_import_removed`.

## 8. Продвинутые классы [S§5], [P§3]

### 8.1. Доступ и испытание

- **Открывается**, когда уровень на начало дня ≥ 20 и прошло ≥ 14 дней от первого игрового дня [S§5 «стартует высоко… с 15-го дня»], дата ≥ `rivalSince`. Пути — два продвинутых класса текущего базового (Странник — один).
- **Испытание** `advanced_trial_started { date, classId }` (продвинутый — со дня после 14-го): дата — сегодня; путь своего базового класса; нет активного испытания; не раньше 7 дней после провала [S§5]. 14 дней, в это время базовый класс не пересчитывается [S§5].
- **Условия испытания (на ревью владельца — «в документе систем», но не даны):** за 14 дней ≥ 10 засчитанных в серию дней **и** ≥ 8 выполненных заданий с главным навыком из фокуса пути (§8.3). Решается при закрытии 14-го дня; дни отдыха и восстановления продлевают окно (не считаются в 14) **(моё решение)**.
- Успех — класс фиксируется до конца сезона [S§5]. Провал — повтор через 7 дней или другой путь. `advanced_trial_abandoned` — отказ (как провал).
- **Новый сезон:** продвинутый остаётся, если базовый класс тот же; в первые 7 дней сезона можно перейти на другой путь того же базового без испытания (`advanced_path_switched`) [S§5]. Если базовый сменился — продвинутый снимается в начале сезона, Мастер предлагает испытание **(моё решение о сроке)**.

### 8.2. Сила

- Пассив базового класса ×2 («+10% → +20%» [S§5]); у Паладина серия +2% сверх базы вместо +1% (у Крестоносца — своё, §8.3). Сила по форме пары — как у базового (Глубина §4.3).
- Первая способность остаётся; вторая — своя, тоже раз в игровую неделю, отдельный счётчик.

**Механики второй способности** (закрытый словарь, событие `ability_used` с `ability` из нового списка, валидация как Глубина §4.4):
- `quest_mult` — задание сегодняшнего дня с главным навыком из фокуса: `mult × k` вне потолков (как «Рывок»).
- `day_mult` — день: условие дня (если есть) проверяется при закрытии; строка `source: 'ability'`, id `ability:<id>:<date>` = XP подходящих заданий дня × (k − 1).
- `guard` — N дней с даты: «Стена» — день не уменьшает серию и не сбрасывает окно лестниц (как заморозка, без траты); «Бастион» — слагаемое короткой ночи Усталости = 0.
- `pledge` — N дней с даты: каждый день засчитан в серию и (Обет) выполнено задание выбранного навыка / (Пост) нет срыва выбранной грани. Успех на закрытии N-го дня — строка `ability:<id>:<date>` = база ранга-потолка навыка × N × (k − 1) (Обет C: 70 × 7 × 1 = 490) **(моё решение — фиксированная формула вместо пересчёта заданий)**. Провал — ничего.
- `invest` — 300 золота списываются как платная трата дня (очередь трат Ядро §7.3); через 7 дней, если доля недели ≥ 70%, — `+450` строкой `invest:<date>`; иначе вклад сгорает.
- `chain` — следующая начатая в этот день цепочка помечена: финал ×2.
- `card` — только отметка недели; карточка рисуется на устройстве.

## 9. Финал сезона [S§8], [P§6]

## 10. Итоги месяца и точка решения [P§8]

- `monthReview(state, month)` — три проверки [P§8]:
  1. **открывал приложение** ≥ 25 из 31 дня (доля 25/31 для любого месяца): день открытия — игровая дата любого события с `deviceId ≠ 'shortcuts'` (Worker пишет сигналы от имени `shortcuts`); `GameState.activity.opened` — даты за 400 дней;
  2. **выполнял в среднем** ≥ 60% заданий: Σ выполнено / Σ выдано по `history` месяца (без своих — как в ранге недели);
  3. **реальный сдвиг** (хоть один): лестница прошла ступень в месяце; «отложено» месяца > 0; прирост Основы ≥ 3 у любой характеристики; навык поднялся на уровень.
- Экран «Итоги месяца» (Анализ → Прогресс → «Итоги января»): три строки с галочками и числами, вердикт [P§8]: «Всё так — можно звать друзей (вторая фаза)» / «Смотрим, что мешает, и упрощаем». В дату `BALANCE.rival.decisionDate` (`'2027-01-31'`) и 7 дней после — карточка на Главной. Суммы в «сдвиге» не показываются, только «есть накопления».

## 13. Мои решения (сводка)

1. Отложены: недельные ×3 + сундук и калибровка шаблонов (до итогов января), легендарный класс, ролик, «подушка», PDF/XLSX.
2. `rivalSince`: награды этапа — только с даты выхода; значения рекордов и индекс — по всей истории.
3. Призрак: день прошлого месяца с тем же числом, несуществующий день — 0; неделя — все 7 дней с призраком; сезонный призрак только показом.
4. Индекс — по XP/день рабочих дней; база 150, если у прошлого месяца < 14 рабочих дней.
5. Рекорд: первое значение без награды; серия — награда раз за серию; дневной предел страниц и фокуса.
6. Карточка без финансовых сумм; рисование — чистые операции + canvas.
7. Лимит месяца фиксируется на начало месяца (первый лимит — сразу); недельный лимит — пропорция по дням; «учёт активен» 3/7 и 15 дней.
8. Бюджетная неделя — третье недельное при наличии лимитов; месяц в лимите 140/200 XP, «10% дохода» 49/70 XP по доле авто-данных.
9. «Отложено» — явные записи копилки, не «доход − расход».
10. Импорт: только CSV, ключ строки с номером повтора, дубль Wallet — та же сумма ±1 день, сопоставление в `replay`.
11. Вердикты бюджета — монотонны: поздний импорт не меняет выданные награды.
12. Продвинутые: условия испытания 10/14 и 8 заданий фокуса (на ревью); соло-замены «Влияния», «пати», «новых мест»; «Аудит» без ИИ; механики второй способности — закрытый словарь из 7.
13. Разбор сезона — `ai_report` с `scope: 'season'`, вход — отдельный белый список без финансов.
14. День открытия — событие не от `shortcuts`.
15. Валюта — настройка устройства.

# Life RPG v2 — этап 3 «Автоматика». Дизайн

Дата: 2026-11-20. Срок по [P§8]: 2–8 декабря 2026. Цель этапа — «шаги и сон засчитываются без тебя»: данные из «Команд» приходят на `/sync`, задания с авто-целью закрываются сами (проверка «авто» ×1,0), считаются HP, Energy, Фокус и Усталость, появляется режим восстановления.

Источники (у владельца, в репозиторий не копируются): **[S]** «детальная проработка систем» — при расхождении побеждает он; **[P]** «личная версия». Конвенции, `BALANCE`, леджер, типы дней, закрытие дня — из спеки «Ядра» `2026-11-19-life-rpg-v2-core-design.md` (дальше «Ядро §N»).

Репозиторий публичный. В коде, тестах, фикстурах и руководстве нет мест, адресов, работодателя, города, сумм доходов и целей владельца. Места в данных — только обобщённые id `gym | work | home`; названия магазинов из Wallet живут только в журнале владельца (его D1 + устройство).

## 1. Что входит и что нет

| Входит | Где |

| Штраф Усталости к XP, множитель Фокуса к Интеллекту | §5.5 |
| Режим восстановления [S§3] | §6 |

| Таймер фокуса и чтения в приложении (источник «авто») | §8 |
| Главная: HP/Energy/Фокус/Усталость, свежесть данных, подсказки | §9 |
| Утренний пуш сразу после синка сна | §10 |
| Руководство по «Командам» для неспециалиста | §11 |

Отложено (§13): срыв вредной привычки (+5 Усталости — нужна Тень, этап 4), перки, ускоряющие спад Усталости (этап 5), аватар «в таверне» (этап 5), лимиты трат и импорт выписки (этап 6), ИИ-проверка фото (этап 5), Влияние и всё командное (вне плана).

## 2. Архитектура — без смены принципов

- Журнал событий — единственный источник правды. Worker только **разбирает и сохраняет** сырые данные «Команд»; всё производное (засчёт, HP…) считает `replay(events, now)` на устройстве. Фоновая задача [S§12] «при каждом /sync закрыть задания и записать журнал» у нас выполняется так: синк приносит событие → replay при следующем открытии/синке закрывает задания и пишет строки леджера. Отдельной серверной логики игры нет (как в «Ядре»).
- `replay` остаётся чистой и не бросает исключений; новые события валидируются полями, неверное необязательное поле отбрасывается, неверное обязательное — отбрасывает событие.
- Все числа — в `BALANCE` (§12).
- Новый чистый модуль `src/domain/vitals.ts` — формулы §5 без знания о журнале. Replay собирает входы по дням и вызывает его.

## 3. Данные на входе

### 3.1. Тело `POST /sync` (что шлют «Команды»)

Один адрес, `Authorization: Bearer <токен>`, тело — JSON-объект ≤ 256 КБ (как сейчас). Поле `kind` выбирает форму.

**Дневная сводка** — `kind` ∈ `morning | evening | other` (неизвестное значение → `other`, как сейчас):

```json
{
  "date": "2026-12-02",
  "kind": "morning",
  "steps": 1234,
  "sleepMinutes": 452,
  "restingHR": 58,
  "weightKg": 80.1,
  "mindfulMinutes": 10,
  "activeKcal": 310,
  "workouts": [
    { "type": "Традиционная силовая тренировка", "start": "2026-12-02T18:00:00+05:00", "end": "2026-12-02T18:50:00+05:00", "minutes": 50 }
  ],
  "calendar": [ { "title": "…", "start": "…", "end": "…" } ]
}
```

- Обязательна только `date` (`ГГГГ-ММ-ДД`). Остальное необязательно; плоские поля и вложенный `health: {…}` работают оба (вложенный побеждает), как сейчас.
- Новые поля: `mindfulMinutes` (или `mindfulMin`) 0–1440; `workouts[]` — до 50 элементов, `type` — строка (обрезается до 60 символов, любой язык), `start`/`end` — ISO-время (необязательны), `minutes` — 0–1440 (нет — из `end − start`). Элемент-число по-прежнему значит «минуты без типа».
- `sleepMinutes` → `sleepHours` как сейчас; `restingHR` 20–250; `steps` 0–200 000 (диапазон разбора; правдоподобие — §4.3).

**Сигнал** — `kind` ∈ `arrive | app | focus | wallet`:

```json
{ "kind": "arrive", "place": "gym", "at": "2026-12-02T18:05:00+05:00" }
{ "kind": "app",    "app": "social", "state": "open", "at": "2026-12-02T21:10:00+05:00" }
{ "kind": "focus",  "state": "on", "at": "2026-12-02T10:00:00+05:00" }
{ "kind": "wallet", "amount": "1 250,50", "merchant": "Кофейня", "at": "2026-12-02T09:12:00+05:00" }
```

| kind | Поля | Правила разбора |
|---|---|---|
| `arrive` | `place` ∈ `gym, work, home` | другое значение → 400 |
| `app` | `app` ∈ `social, games`; `state` ∈ `open, close` | имя конкретного приложения **не принимается и не хранится** — только группа |
| `focus` | `state` ∈ `on, off` | |
| `wallet` | `amount` — число или строка («₸1 250,50», «-300») → число, \|amount\| ≤ 10 000 000; `merchant` — строка ≤ 60 символов без управляющих символов | возврат — отрицательная сумма |

`at` — ISO-время с поясом. Нет или не разбирается → время сервера. Старше 7 дней или позже сервера больше чем на 10 минут → 400 «Время at вне допустимого окна». Игровая дата сигнала считается на устройстве из `at` (с учётом закрытия дня по отбою — ночные смены, Ядро §6.2), поэтому `date` для сигналов не нужна и игнорируется.

### 3.2. События журнала

```ts
// расширение (только необязательные поля):
| { type: 'health_packet'; date; kind: 'morning'|'evening'|'other'; health: HealthData; calendar }
//   HealthData += mindfulMin?: number; workouts?: { type: string; start?: number; end?: number; minutes: number }[]
// новые:
| { type: 'signal_logged'; at: number /* ms */; signal:
      | { kind: 'arrive'; place: 'gym'|'work'|'home' }
      | { kind: 'app'; app: 'social'|'games'; state: 'open'|'close' }
      | { kind: 'focus'; state: 'on'|'off' }
      | { kind: 'wallet'; amount: number; merchant: string } }
| { type: 'timer_logged'; timer: 'focus'|'reading'; start: number; end: number }   // §8
| { type: 'recovery_started'; date: ISODate; quests: 0|1|2 }                         // §6
| { type: 'recovery_ended'; date: ISODate }
```

`deviceId` событий из `/sync` — `'shortcuts'` (как сейчас).

### 3.3. Ответ

`200 { ok: true, duplicate: boolean, received: {...разобранные поля без merchant...} }`. Ответ показывается в «Командах» при проверке, поэтому название магазина в нём не повторяется.

### 3.4. Идемпотентность

«Команды» повторяют запрос при плохой сети, автоматизации на 13:00 и 18:00 шлют одни и те же тренировки. Две защиты:

1. **Worker:** `id = 'sync-' + первые 32 hex SHA-256(канонический JSON разобранного пакета)`. Тот же пакет второй раз → `INSERT OR IGNORE` ничего не вставляет, ответ `duplicate: true`. Канонический JSON — ключи в фиксированном порядке, без `ts`.
2. **Replay:** тренировки дня объединяются по ключу `start|end|type` (без `start` — `type|minutes`); шаги, осознанность — максимум за дату (накопительные за день значения «Здоровья»); сон, пульс, вес — последнее по `ts`; сигналы с одинаковыми `(kind, at, поля)` считаются одним.

## 4. Из событий — данные дня

### 4.1. `DayData` (внутри replay, по игровой дате)

```ts
interface DayData {
  steps?: number; sleepHours?: number; restingHR?: number; mindfulMin?: number; weightKg?: number;
  workoutMin?: number; strengthMin?: number; mobilityMin?: number; cardioMin?: number; sportsMin?: number;
  focusMin?: number;     // объединение интервалов: «Фокусирование» on→off + таймер фокуса
  readMin?: number;      // таймер чтения
  socialMin?: number; gamesMin?: number;   // сессии open→close
  gymVisits?: number;
  spendAuto?: number;    // сумма Wallet
  flags: DataFlag[];
}
type DataFlag = { metric: 'steps' | 'sleepHours' | 'workouts'; reason: 'too_many_steps' | 'too_long_sleep' | 'overlap' }
```

Ручной `metric_logged` остаётся в `metrics` как сейчас; авто-проверка смотрит только `DayData` (ручной ввод — честное слово, [S§11]).

### 4.2. Типы тренировок (моё решение)

`workoutKind(type)` — регулярные выражения по-русски и по-английски (локализованные имена из «Команд»):

| Вид | Ключевые слова (подстрока, без регистра) |
|---|---|
| `strength` | сил, strength, функц, functional, кроссфит, cross |
| `mobility` | йог, yoga, гибк, flexib, растяж, stretch, пилат, pilates |
| `cardio` | бег, run, вел, cycl, плав, swim, кардио, cardio, hiit, интервал, эллипс, ellip, гребл, row, ходьб, walk, поход, hik |
| `sports` | футб, soccer, баскет, basket, теннис, tennis, волей, volley, бокс, box, единобор, martial, игр, game |
| иначе | `other` — только в `workoutMin` |

Порядок проверки — сверху вниз (первое совпадение). `workoutMin` = сумма всех уникальных тренировок дня.

### 4.3. Правдоподобие [S§11]

| Условие | Флаг | Последствие |
|---|---|---|
| шаги дня > 50 000 | `too_many_steps` | шаги дня не засчитывают задания и не идут в HP |
| сон > 14 ч | `too_long_sleep` | то же для сна (HP, Energy, Усталость, задание «Выспаться») |
| две уникальные тренировки дня пересекаются по времени | `overlap` | все `*Min` тренировок дня не засчитывают задания |

Данные не удаляются и видны в аналитике с пометкой «⚠ похоже на ошибку». Отметить задание вручную можно (честное слово ×0,7). Отдельного «подтвердить данные» нет (моё решение: в соло-версии рейтингов нет, а вручную отметить уже можно).

### 4.4. Авто-засчёт

`Quest.auto.metric` расширяется: `'steps' | 'sleepHours' | 'weightKg' | 'workoutMin' | 'strengthMin' | 'mobilityMin' | 'cardioMin' | 'sportsMin' | 'mindfulMin' | 'focusMin' | 'readMin' | 'gymVisits' | 'socialMin' | 'gamesMin'`.

Правила (сохраняют монотонность Ядро §5.3):

1. `op '>='`: задание засчитывается «авто», если **максимум** незафлаженных значений метрики за дату ≥ цели. Позднее значение меньше (пересинк сна) засчёт не снимает.
2. `op '<='` («без соцсетей», «без игр»): решается **только для закрытого дня** и только если источник жив — за 3 дня до даты включительно был хоть один сигнал этой группы приложений. Иначе — нет авто (отсутствие данных ≠ «не открывал»). Сегодня карточка пишет «засчитается при закрытии дня, если …».
3. Ручная галочка поднимается до «авто», когда данные подтвердили цель (как в Ядре). «Авто» никогда не опускается.
4. Задания, выданные **до** этапа, тоже проверяются по новым правилам, но их `auto` записан в событии — меняется только набор метрик у новых выдач.

Изменения банка заданий (`questBank.ts`, моё решение):

| Шаблон | auto |
|---|---|
| `workout` Силовая тренировка | `strengthMin >= n` (было `workoutMin`) |
| `stretch` Растяжка | `mobilityMin >= n` |
| `ball` Спортивная игра | `sportsMin >= n` |
| `run`, `cardio`, `bike` | `cardioMin >= n` |
| `meditate`, `breath` | `mindfulMin >= n` |
| `focus` Глубокая работа | `focusMin >= n` |
| `read` Прочитать N страниц | `readMin >= minutes(n)` (минуты шаблона: 1,5 мин на страницу) |
| новый `gym` «Сходить в зал» (Силовые, весь день) | `gymVisits >= 1` |
| `no_social`, `no_games` | `socialMin <= 5`, `gamesMin <= 5` (5 минут — «глянул уведомление», моё решение) |

`sleep`, `steps` — как были.

## 5. Производные параметры [S§3]

Все функции — в `vitals.ts`, возвращают целое 0–100 или `null` (ни одного источника). Отсутствующий источник выбывает, его вес делится между остальными пропорционально: `Σ wᵢ·sᵢ / Σ wᵢ` по доступным.

### 5.1. HP — по дню `d`, окно `d−2…d`

| Часть | Вес | Балл |
|---|---|---|
| Сон | 0,4 | `sleepScore(среднее сна за окно)`: 7–9 ч → 100; меньше 7 — `100 − 20 × (7 − h)`; больше 9 — 100 (документ молчит, моё решение); ≥ 0 |
| Активность | 0,3 | `min(100, 100 × среднее шагов за дни окна с данными / цель)`; цель = `profile.stepsUsual`, нет/0 → 6 000 |
| Пульс покоя | 0,2 | `100 − 10 × max(0, ср. пульс окна − ср. пульс 30 дней до окна)`; нужно ≥ 5 значений за 30 дней, иначе источника нет |
| Самочувствие | 0,1 | энергия вечернего чек-ина за окно (среднее, 1–10): ≥ 8 → 100, иначе ×10 |

Зафлаженные значения не участвуют. Примеры (тесты): сон 6 ч → 80; шаги 3 000 при цели 6 000 → 50; пульс 63 при среднем 60 → 70; самочувствие 6 → 60; HP = 0,4·80 + 0,3·50 + 0,2·70 + 0,1·60 = **67**. Только сон 7,5 ч → **100**.

### 5.2. Energy — утром дня `d`

`Energy = 0,6 × sleepScore(сон ночи d) + 0,25 × утренняя оценка × 10 + 0,15 × HP(d)`.

- Утренняя оценка — `day_started.energy` (1–10, из «Моего дня»). Нет — среднее утренних оценок за 7 прошлых дней; нет и их — источник выбывает.
- Пример: сон 6 ч (80), оценка 7, HP 67 → 48 + 17,5 + 10,05 = **76**. Без оценки, среднее недели 6 → **73**. Без оценок вообще → (48 + 10,05) / 0,75 = **77**.
- Ничего нет (нет сна, оценок, HP) → `BALANCE.energy.fallback` 50, как в Ядре.
- **Моё решение про «до 10:00»:** день собирается в «Моём дне» в момент старта, ждать до 10:00 нельзя. Поэтому правило «нет чек-ина до 10:00 — среднее за неделю» применяется в момент сборки: не поставил оценку при старте — берётся среднее. Сборка использует Energy на момент старта; `today.energy` на Главной — живое значение (меняется, когда придёт сон).

### 5.3. Фокус — за день `d`

`Фокус = 0,7 × min(100, focusMin / 90 × 100) + 0,3 × socialScore`, `socialScore`: ≤ 30 мин → 100, ≥ 120 → 0, между — линейно.

- Источник «фокус» есть, если за 14 дней был хоть один сигнал `focus` или таймер фокуса; «соцсети» — хоть один сигнал `app/social`. Нет источника — вес делится; нет обоих — `null`.
- Сессии: `open→close` одной группы — длительность; `open` без `close` — до следующего сигнала этой группы, но не больше 15 минут; `close` без `open` игнорируется; одна сессия ≤ 180 минут. Интервалы фокуса (режим + таймер) объединяются (без двойного счёта), один интервал ≤ 240 минут. Сессия относится к игровой дате своего начала.
- Примеры: 90 мин фокуса, 30 соцсетей → **100**; 45 и 75 → **50**; 0 и 120 → **0**.

### 5.4. Усталость — накопительная

Рекуррентно от первого дня с заданиями (до него 0), на начало дня `d`:

```
F(d) = clamp(F(d−1) + день(d−1) + ночь(d) − 5, 0, 100)
ночь(d):  сон ночи d < 6 ч → +15;  ≥ 7,5 ч → −20;  нет/зафлажен → 0
день(d−1): XP дня > 150% обычного → +10   (обычный = средний XP за 14 прошлых закрытых не-отдыхающих дней; нужно ≥ 7 таких дней)
           день отдыха (тип rest, «день без заданий», замороженный день восстановления) → −15
           выполнено задание навыка mindfulness/rest, или шаблон stretch, или mindfulMin ≥ 10 → −10 (один раз в день)
           энергия вечернего чек-ина 1–3 → +5
```

- **Моё решение:** ночь учитывается на начало дня, к которому относится сон (сон приходит утренним синком этой даты), — так утренний штраф и сборка видят прошедшую ночь. «Сама −5 каждую ночь» — слагаемое `−5`.
- Пример (тест): с нуля шесть ночей по 5 ч без других событий: 10, 20, 30, 40, 50, **60** → на 6-й день сборка ставит обязательное задание на Дух; на 7-й **70** → предложение режима восстановления.
- Срыв вредной привычки (+5) — этап 4 (нужна Тень).

### 5.5. Влияние на XP

- **Штраф Усталости** `F(d) × 0,3%` добавляется в список штрафов формулы награды Ядро §5.3 (общий потолок штрафов 0,5 сохраняется). F = 40, задание C «честное слово»: 70 × 0,7 × (1 − 0,12) = **43**.
- **Множитель Фокуса** `0,8 + 0,4 × Фокус/100` — для заданий с главной характеристикой Интеллект, множится в `mult` (вне потолков, как «Вернуть форму»). Фокус `null` → ×1. Задание C авто при Фокусе 100 → **84**; при 0 → **56**.
- **Моё решение:** Фокус берётся за **тот же** день (документ: «за день»). XP сегодняшних заданий Интеллекта может сдвинуться, пока копятся минуты; закрытый день окончателен. В строке леджера `mult` и `penalty` видны — это объясняет число.

### 5.6. Снимок дня

`DayResult` получает `hp`, `energy`, `focus`, `fatigue` (число или `null`) — это `daily_state` [S§12] для графиков.

## 6. Режим восстановления [S§3]

- `recovery_started { date, quests }` — кнопка на Главной или в «Моём дне», выбор «0 / 1 / 2 лёгких задания». `recovery_ended { date }` — кнопка «Вернуться». Повторный старт при активном режиме меняет только `quests`; конец без начала игнорируется; события с датой в будущем (> сегодня) игнорируются.
- Действует с `date` старта по день перед `recovery_ended.date` включительно (день выхода — обычный). Фраза Мастеру («заболел») — этап 5.
- **Заморозка:** день восстановления, как день отдыха Ядро §6.5 — серия не меняется, день не входит в окна Формы, ослабление не копится, Усталость −15. Лестницы и лига — этапы 4–5, у них будет тот же признак `frozen`.
- **Лимит 14 дней в календарный месяц — общий** со днями типа `rest` и купленными «днями без заданий» (`restInMonth` Ядра). Сверх лимита режим остаётся включённым, сборка остаётся лёгкой, но день — обычный: серия и форма считаются («мягкий режим без заморозки»).
- **Сборка в режиме:** `quests` заданий (0–2), ранг на 1 ниже потолка, только навыки `mindfulness, rest, reflection, sleep, mobility`, без вызова. Сон ≥ 7,5 ч засчитывает «Выспаться» как обычно — «отдых и сон дают XP в Дух и Выносливость».
- **Подсказки:** вход — Усталость ≥ 70 или HP < 40 (баннер «Мастер предлагает режим восстановления»); выход — режим активен и HP > 60 сегодня и вчера.
- **Возвращение:** 2 дня, начиная с `recovery_ended.date`, все задания сборки на ранг ниже, без вызова. Без нажатия «Вернуться» режим не заканчивается сам.
- Командные последствия (гильдия, рейды) — вне плана.

## 7. Сборка дня — изменения [S§6]

`AssembleCtx` += `fatigue: number`, `recovery: { active: boolean; quests: 0|1|2 } | null`, `afterRecovery: boolean`; `energy` теперь из §5.2.

1. Energy < 40 → −1 слот, без вызова, физические не выше D, одно задание на Дух (уже в Ядре).
2. Energy ≥ 70 → +1 вызов (уже в Ядре).
3. **Новое:** Усталость > 50 → обязательное задание на Дух (в счёт слотов, одно на день вместе с правилом Energy < 40).
4. **Новое:** режим восстановления и 2 дня после — §6.
5. «Сходить в зал» — обычный кандидат Силовых; засчитывается автоматически по прибытию.

## 8. Таймер фокуса и чтения (моё решение — делаем, дёшево)

- Лист «Таймер» с Главной (кнопка на карточке задания `focus`/`read` и общий вход): режим «Фокус» или «Чтение», старт/стоп. Время считается по часам (`Date.now()` старта хранится в `localStorage`), фоновая вкладка не сбивает счёт.
- На «Стоп» пишется `timer_logged { timer, start, end }`. Replay принимает, если `0 < end − start ≤ 240 мин`, `end ≤ ts события + 1 мин`; пересекающиеся таймеры одного вида объединяются.
- Источник [S§11] «таймер в приложении» = **авто** ×1,0.
- Вода остаётся ручным вводом (есть в «Быстром вводе»), проверка — честное слово: ручной ввод не авто.

## 9. Интерфейс

- **Главная, HUD:** четыре стеклянные плашки HP · Energy · Фокус · Усталость (число 0–100 и тонкая полоска; `null` → «—» и подсказка «нет данных»). Нажатие раскрывает разбор: «Сон 80 · Шаги 50 · Пульс 70 · Самочувствие 60». Цвета — токены `:root`, у Усталости шкала обратная.
- **Свежесть:** строка «Данные: 2 ч назад» из последнего события с `deviceId 'shortcuts'`; старше 36 ч — «Команды давно не присылали данные» со ссылкой на руководство.
- **Баннеры** (не больше одного, по приоритету): предложение режима восстановления; предложение выйти; «Похоже, ты на работе — сменить тип дня?» (прибытие `work` в день типа `off`/`rest` — только подсказка, событие пишет пользователь кнопкой, моё решение вместо автосмены); пометка правдоподобия.
- **Карточка задания с `auto`:** «засчитается само: шаги ≥ 9 000 (сейчас 6 120)»; для `<=` — «при закрытии дня».
- **Режим восстановления:** лист с выбором 0/1/2, остатком «дней в месяце: N», кнопкой «Вернуться»; на Главной — плашка «Отдых в таверне».
- **«Мой день»:** оценка 1–10 как сейчас; Energy для сборки — `energyScore` с этой оценкой.
- **Настройки → Синхронизация:** «Последние данные по источникам»: сводка «Здоровья», прибытие, приложения, фокус, Wallet — время последнего сигнала каждого вида.

## 10. Напоминания (пуши)

Утренний пуш этапа «Ядро» остаётся по времени. **Новое (моё решение):** когда приходит `/sync` `kind: 'morning'` со сном, Worker сразу шлёт утренний пуш тем подпискам, кому он за эту локальную дату ещё не уходил, и отмечает его отправленным — пуш приходит после подъёма, а не в фиксированный час. Текст: «Сон 7,6 ч засчитан. Открой «Мой день» — задания ждут». Кроме часов сна Worker ничего не знает (состояние игры на устройстве), поэтому подсказка про режим восстановления — только баннер в приложении. Вечерний пуш без изменений.

## 13. Приватность

- Транзакции (сумма, магазин), сессии приложений (только группа и время), прибытия (только `gym/work/home` и время) хранятся в журнале: D1 в Cloudflare-аккаунте владельца + Dexie на его устройствах. Больше нигде.
- **ИИ:** согласие на ИИ сейчас одно — владелец сам вводит ключ (`AiPanel`). Промпты собираются по **белому списку** полей: `questContext` и недельный отчёт получают только шаги, сон, чтение, воду, настроение, экранное время (ручное), тренировки (минуты) и HP/Energy/Фокус/Усталость числами. ## 15. Мои решения (заполненные пробелы)

1. Worker не считает игру: засчёт на `/sync` делает replay на устройстве.
2. Сигналы несут `at`, игровая дата — на устройстве по закрытию дня.
3. Идемпотентность — id из хэша пакета + слияние тренировок по `start|end|type`.
4. Типы тренировок — по ключевым словам, порядок §4.2.
5. Зафлаженные данные не засчитывают и не влияют на параметры; кнопки «подтвердить» нет.
6. `<=`-задания — только при закрытии дня и при живом источнике за 3 дня; порог 5 минут.
7. Новый шаблон «Сходить в зал» — авто по прибытию.
8. Сон > 9 ч — 100 баллов.
9. Пульс: нужно ≥ 5 значений за 30 дней.
10. Самочувствие — энергия вечернего чек-ина.
11. Energy фиксируется для сборки в момент старта дня; «до 10:00» = «при старте».
12. Фокус влияет на XP Интеллекта того же дня; закрытый день окончателен.
13. Сессия без закрытия — до 15 минут; сессия ≤ 180, интервал фокуса ≤ 240.
14. Ночь входит в Усталость на начало своего дня.
15. Срыв привычки (+5) — этап 4.
16. Режим восстановления делит лимит 14 дней с днями отдыха и «днями без заданий»; сверх — лёгкая сборка без заморозки.
17. Тип дня `rest` остаётся как однодневный отдых.
18. Автосмена дня по прибытию — только подсказка.
19. Таймер фокуса и чтения — делаем; вода остаётся ручной (честное слово).
20. Утренний пуш уходит сразу после синка сна, если ещё не уходил.
21. Белый список полей для ИИ; Wallet, сессии, места — никогда.

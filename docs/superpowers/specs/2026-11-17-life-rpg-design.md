# Life RPG — дизайн

Дата: 2026-11-17. Статус: черновик на согласование.

## 1. Зачем это

Владелец (единственный пользователь) хочет развиваться, но стоит на месте из‑за нехватки дисциплины и много времени проводит в играх. Его цепляют в играх **соревнование и демонстрация мастерства**. Приложение должно превратить реальную жизнь в игру, где реальные поступки качают аниме‑персонажа, а соперник — **собственная Тень** (лучшая версия его прошлых результатов).

Вдохновение — Life Reset 66 days (реальные действия → прокачка персонажа), но **без 66‑дневного лимита**: прогрессия бесконечная, приложение каждый день само анализирует данные и подстраивает (обычно — повышает) сложность.

Распорядок пользователя: подъём ~10:00, но плавает; ложится поздно; большая часть дня — работа. Свободные окна короткие и непостоянные.

Пользователь не программист: все инструкции — пошаговые, «по одному действию».

## 2. Цели

- PWA на iPhone (iOS 27, Safari → «На экран Домой»), полноэкранная, офлайн, safe‑area, интерфейс на русском.
- Онбординг‑анкета → стартовые характеристики → настройка «Команд» и проверка первой синхронизации.
- Аниме‑аватар, сгенерированный ИИ по фото пользователя, с этапами образа по уровню.
- Тень — соперник, видна на главном экране рядом с аватаром.
- Ежедневный цикл: утренние задания в свободных окнах, автозачёт по данным здоровья, вечерний чек‑ин, адаптация сложности на завтра.
- Автосбор данных через iOS «Команды» → `POST /sync` на бесплатный бэкенд.
- Геймификация: серии, ежедневные/недельные/босс‑задания, достижения, мягкие штрафы, дерево навыков, валюта и магазин наград (награды задаёт пользователь).
- Аналитика: графики характеристик и показателей, недельный отчёт ИИ.
- Уведомления (Web Push) утром и вечером.
- Экспорт/импорт всех данных в JSON.

## 3. Не‑цели

- Никаких других людей: ни друзей, ни лидербордов, ни аккаунтов. Один пользователь.
- Никаких платных сервисов как обязательного условия. ИИ — опционально по ключу пользователя.
- Не App Store, не нативное приложение.
- Не 66‑дневный курс с концом.

## 4. Анти‑цели (провал, даже если «работает»)

- Жёсткие штрафы, которые обнуляют прогресс и демотивируют («сломался на 2‑й неделе»).
- Задания, не влезающие в реальный день (стоят на рабочее время, требуют часа, когда окно 15 минут).
- Сложность, которая растёт механически и не учитывает провалы и энергию.
- Приложение без ключа ИИ ощущается пустым/сломанным.
- Данные пользователя (фото, здоровье) уходят куда‑то, кроме его собственного бэкенда и выбранного им ИИ‑провайдера.

## 5. Решения пользователя

- Соперник — **своя Тень**, не другие люди.
- Аватар — **аниме‑стиль, генерируется по фото внутри приложения** по ИИ‑ключу. Ключ пользователь добавит позже.
- Прогрессия **постоянная**, без 66‑дневного цикла; сложность адаптируется ежедневно по данным.
- Выбор ИИ‑провайдера отложен; в настройках должны быть варианты.
- Есть аккаунт GitHub. iPhone на iOS 27.
- **Приложение открывается и на iPhone, и на компьютере**, данные везде одинаковые (полная синхронизация через бэкенд). Это заодно и бэкап.
- **График работы плавающий**: каждое утро пользователь одним касанием указывает, когда сегодня работает (шаблоны + «выходной»).
- **Только iPhone, без часов**: автоматически приходят шаги (и вес, если вводится в «Здоровье»); сон — только если включено «Расписание сна» (время «в кровати»); тренировки, пульс покоя — нет или вручную.

## 6. Технический стек (решение ассистента)

| Слой | Выбор | Почему |
|---|---|---|
| Фронтенд | React 18 + Vite + TypeScript | просил React+Vite; TS ловит ошибки, которые новичок не найдёт |
| PWA | `vite-plugin-pwa` (Workbox, injectManifest) | манифест + SW + офлайн; свой SW нужен для push |
| Локальные данные | IndexedDB через Dexie | офлайн, блобы картинок |
| Графики | Recharts | |
| Хостинг фронта | GitHub Pages через GitHub Actions | аккаунт уже есть |
| Бэкенд | Cloudflare Worker + D1 (SQLite), Cron Triggers | бесплатно; D1 удобнее KV для журнала событий с выборкой «новее чем» и даёт 100k записей/день |
| ИИ‑текст | Gemini / Claude / OpenAI — запросы прямо из браузера по ключу из настроек | без своего сервера; ключ только на устройстве |
| ИИ‑картинки | Gemini (image‑модель, принимает фото) или OpenAI image | Claude картинки не рисует |

Стиль UI: тёмный аниме‑интерфейс с неоновыми акцентами («системные» панели, светящиеся рамки, фиолетовая Тень) — ближе всего к варианту C из макетов, но в аниме‑стилистике. Оригинальный, не копия конкретной игры/аниме.

## 7. Архитектура

```
iPhone «Команды» ──POST /sync (Bearer)──► Cloudflare Worker ──► D1 (журнал событий)
PWA на iPhone  ─┐                              ▲      │ Cron каждые 15 мин
PWA на ПК      ─┴─ POST /events, GET /events?since ┘      └─► Web Push
   │  IndexedDB (локальная копия, офлайн)
   └─► ИИ‑провайдер напрямую (ключ пользователя)
```

- **Журнал событий (event log) — общий источник истины.** Всё, что меняет игру, — неизменяемое событие с `id` (UUID), `deviceId`, `ts`, `type`, `payload`: пакет здоровья, онбординг, выданные задания дня, отметка задания, ручной ввод, чек‑ин, покупка, открытие навыка, смена аватара, изменение настроек игры. Состояние (XP, характеристики, Тень, серии) **вычисляется** детерминированно, проигрыванием журнала; кэш состояния в IndexedDB — только для скорости.
- Офлайн: события копятся в IndexedDB с флагом `pending`, при сети отправляются пачкой `POST /events`. Дубликаты отсекаются по `id`.
- При каждом открытии (и при возврате в приложение): отправить pending → `GET /events?since=<серверный курсор>` → добавить → пересчитать.
- **Задания дня генерирует первое устройство**, открытое в новые игровые сутки, предварительно сделав pull. Если два устройства сгенерировали офлайн одновременно — побеждает событие с меньшим `ts`, второе игнорируется.
- Настройки устройства (ИИ‑ключ, push‑подписка) **не** синхронизируются — у каждого устройства свои. ИИ‑ключ никогда не уходит на бэкенд.
- Вход на втором устройстве: ввести URL бэкенда и токен (или отсканировать QR из настроек iPhone) → полный pull.

### Эндпоинты Worker

Все, кроме `/register`, требуют `Authorization: Bearer <SYNC_TOKEN>`; сравнение — в постоянном времени. CORS — только origin приложения (+ запросы без Origin от «Команд»).

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/register` | принимает токен, сохраняет его хэш в KV **только если токена ещё нет** (одноразово). Дальше → 409 |
| POST | `/sync` | принимает JSON от «Команд», валидирует (размер ≤ 256 КБ, схема), пишет событие `health_packet`; отвечает `{ok, received:{…кратко}}` |
| POST | `/events` | пачка событий от приложения (≤ 500 шт., ≤ 1 МБ), `INSERT OR IGNORE` по `id` |
| GET | `/events?since=<seq>` | события с серверным порядковым номером > `seq` (страницами по 1000) |
| PUT/GET | `/blob/<name>` | картинки аватара (≤ 2 МБ, WebP), чтобы они были на всех устройствах |
| GET | `/ping` | проверка соединения и токена, время последнего `/sync` |
| POST | `/push/subscribe` | сохраняет push‑подписку и время утреннего/вечернего уведомления |
| Cron | каждые 15 мин | если наступило время — шлёт push (VAPID) |

События не удаляются (это история игры; объём — единицы МБ в год, бесплатный D1 даёт 5 ГБ).

**Токен (решение ассистента):** приложение при онбординге генерирует 32‑байтный случайный токен, вызывает `/register` и показывает токен в «Настройки → Синхронизация» с кнопкой «Скопировать». Пользователю не нужно трогать консоль Cloudflare для секретов. Есть кнопка «Сбросить токен» (требует старый токен).

### Формат пакета `/sync`

```json
{
  "date": "2026-11-17",
  "sentAt": "2026-11-17T21:05:00+03:00",
  "kind": "evening",
  "health": {
    "steps": 8421,
    "sleepHours": 6.8,
    "workouts": [{"type": "Бег", "minutes": 32, "kcal": 310}],
    "activeKcal": 540,
    "restingHR": 61,
    "weightKg": 78.4
  },
  "calendar": [
    {"title": "Работа", "start": "2026-11-17T11:00:00+03:00", "end": "2026-11-17T20:00:00+03:00"}
  ]
}
```

Все поля health опциональны (если «Здоровье» пусто — их нет). «Команды» отдают значения как текст/списки; Worker и клиент должны терпеть числа строками, запятые как десятичный разделитель и пустые значения. Сон — сумма интервалов «Сон» за прошедшую ночь.

| Таблица | Ключ | Содержимое |
|---|---|---|

| `character` | `id=1` | имя, уровень, XP, валюта, класс, титул, параметры аватара (волосы, одежда, акценты — для промпта) |

| `quests` | `id` | дата, тип (daily/weekly/boss), заголовок, окно времени, длительность, сложность 1–5, XP, характеристика, условие автозачёта (`{metric, op, value}` или null), статус, источник (rules/ai) |

| `achievements` | `id` | дата получения |
| `skills` | `id` | открытые узлы дерева навыков |

Экспорт: весь Dexie → один JSON (блобы в base64), версия схемы в файле. Импорт заменяет данные после подтверждения.

## 9. Игровая механика

**Характеристики (7):** Сила, Выносливость, Интеллект, Дисциплина, Харизма, Финансы, Дух. Старт 1–20 из анкеты (честные низкие значения — норм, так видно рост).

**XP и уровень:** XP за уровень `L → L+1` = `round(100 · L^1.5)`. XP задания = база по сложности (10/20/35/55/80) × множитель сложности. Каждое задание также даёт +очки своей характеристике; 10 очков = +1 к характеристике. Валюта = 10% от XP.

**Классы:** по двум самым высоким характеристикам (например, Сила+Выносливость → Воин, Интеллект+Дисциплина → Стратег, Харизма+Дух → Лидер, Финансы+Дисциплина → Торговец …, всего ~10 комбинаций). **Титулы** — за достижения и серии.

**Этапы образа:** 4 тира: ур. 1–4, 5–14, 15–29, 30+. На каждом новом тире предлагается сгенерировать новый образ (одежда/экипировка богаче, аура).

**Тень:** каждый день у Тени есть «XP дня» = 75‑й перцентиль твоего дневного XP за последние 14 дней × (1 + 0.02 × число побед подряд), плюс цели по метрикам = твой лучший 7‑дневный средний × 1.05. Метрики Тени — только те, по которым есть данные (у пользователя без часов: шаги, плюс сон/чтение/вода/экранное время, если вводятся).

**Автозачёт без часов:** автоматически — задания на шаги (и вес). Сон — авто, если в «Здоровье» есть данные «Расписания сна», иначе ручная отметка. Тренировки — ручная отметка («Сделал тренировку: тип, минуты»). Банк заданий не должен опираться на пульс покоя. Главный экран: «Ты N XP · Тень M XP» и полоски по метрикам. Победа дня → +бонус XP и титулы серий; проигрыш → Тень «уходит вперёд» (визуально), без отнятия прогресса. Тень = твой аватар с CSS‑фильтром (затемнение + фиолетовое свечение).

**Адаптивная сложность (каждый вечер, без ИИ — по правилам):**
- для каждой характеристики смотрим выполнение её заданий за 7 дней:
  - ≥ 85% → множитель × 1.10; 50–85% → без изменений; < 50% → × 0.85;
- энергия чек‑ина ≤ 4 → завтра на 1 задание меньше и без сложности ≥ 4;
- сон < 6 ч (по «Расписанию сна» или по ручному вводу) → завтрашние физические задания легче; нет данных о сне — правило не применяется;
- множитель в диапазоне 0.5–3.0.
С ключом ИИ — ИИ получает этот расчёт и данные за 14 дней и может скорректировать (в тех же границах).

**Утренний экран «Мой день»** (перед выдачей заданий, 1 касание): «Сегодня работаю: [шаблон 1] [шаблон 2] [выходной] [другое время]». Шаблоны пользователь задаёт в анкете. Подъём = время этого касания (или конец сна из «Расписания сна», если есть). В течение дня — кнопка «Занят до …», которая переносит задания.

**Утренний набор (без ИИ — правила):**
1. Свободные окна = от подъёма до сна (сон из анкеты) минус рабочее время дня минус события календаря.
2. 3–7 заданий (по энергии и вчерашнему выполнению). Минимум 1 на самую слабую характеристику, 1 «авто» (шаги/сон/тренировка), остальное — по целям анкеты и вредным привычкам («без игр до 20:00»).
3. Задание ставится в окно, куда помещается по длительности; ценно ставить на время высокой энергии из анкеты.
Встроенный банк ~80 шаблонов заданий по 7 характеристикам, с длительностью и автоусловием, где применимо.

**Недельные задания** — 2–3 на неделю (например, «4 тренировки», «50 000 шагов»). **Босс‑задания** — большие цели из анкеты, разбитые на этапы; этап = задание повышенной награды.

**Мягкие штрафы:** пропущенное задание → −50% от его XP в «долг Тени» (Тень получает их), серия сгорает. Уровень и характеристики не падают никогда.

**Серии:** дни подряд с ≥ 1 выполненным заданием; отдельная серия «побед над Тенью».

**Дерево навыков:** по ветке на характеристику, узлы открываются за очки навыков (1 за уровень) и дают пассивные бонусы (+XP к типу заданий, «заморозка серии» раз в неделю и т. п.).

**Магазин наград:** пользователь сам создаёт награды и цену в валюте («1 час игр — 150 монет»). Покупка списывает валюту и пишется в журнал.

**Ручной быстрый ввод:** один экран с крупными кнопками: экранное время, траты, настроение (1–5), вода (+стакан), чтение (страницы/минуты).

## 10. Экраны

1. **Онбординг** (пошаговая анкета, ~10 шагов) → расчёт характеристик → фото/аватар (можно пропустить) → настройка «Команд» + проверка синхронизации.
2. **Главная:** аватар и Тень, уровень/XP, счёт дня против Тени, задания на сегодня, кнопка быстрого ввода.
3. **Персонаж:** характеристики, класс, титул, дерево навыков, достижения, редактор образа (волосы, одежда, цвет, аксессуары → перегенерация).
4. **Задания:** сегодня / неделя / боссы.
5. **Аналитика:** графики характеристик и метрик, недельный отчёт ИИ.
6. **Магазин** наград.
7. **Вечерний чек‑ин.**
8. **Настройки:** ИИ‑провайдер и ключ, уведомления, синхронизация (время последней передачи, что пришло, «Проверить соединение», токен), экспорт/импорт.

## 11. ИИ

- Провайдеры в настройках: Gemini (рекомендуется: бесплатный лимит, текст + картинки), Claude, OpenAI. Ключ хранится только в IndexedDB.
- Вызовы из браузера напрямую. Для Claude нужен заголовок `anthropic-dangerous-direct-browser-access: true`.
- Задачи ИИ: утренний набор заданий (строгий JSON по схеме заданий), вечерняя корректировка сложности, недельный отчёт (закономерности, слабые места, рекомендации), генерация аватара по фото.
- Любой ответ ИИ валидируется; при ошибке/таймауте/отсутствии ключа → правила. Приложение всегда работает без ИИ.
- Аватар: фото + параметры редактора + тир → промпт «аниме‑портрет в полный рост этого человека, сохранить черты лица, [одежда тира], прозрачный/тёмный фон». Пока ключа нет — встроенный нейтральный SVG‑силуэт в аниме‑стиле. Перед первой отправкой фото — явное предупреждение, что фото уйдёт выбранному провайдеру.

## 12. Уведомления

- Web Push (iOS 16.4+ для установленных PWA). Подписка — по нажатию кнопки (iOS требует жеста пользователя).
- Утро (время из анкеты/настроек): «Задания на сегодня готовы». Вечер: «Время чек‑ина. Тень впереди на N XP?» — текст без данных, т. к. Worker их не знает; конкретика — в приложении.
- VAPID‑ключи генерируются при деплое Worker.

## 13. «Команды» iOS

Пошаговая инструкция (каждое действие отдельно), отдельный документ `docs/shortcuts.md` и экран в онбординге:
- действия «Найти образцы здоровья» для шагов, сна, тренировок, активных ккал, пульса покоя, веса за сутки; «Найти события календаря» на сегодня и завтра;
- «Словарь» → «Получить содержимое URL» (POST, JSON, заголовок Authorization);
- автоматизации «Время суток» (утро и вечер) с выключенным «Спрашивать до запуска».
Инструкцию нужно проверить на реальной версии «Команд» iOS 27 — названия действий могли измениться.

## 14. Этапы

1. **MVP:** онбординг, характеристики, аватар‑заглушка + Тень, экран «Мой день», задания по правилам, ручная отметка, XP/уровни/классы, быстрый ввод, чек‑ин, экспорт/импорт, PWA на GitHub Pages. **Сразу на журнале событий** (локально), чтобы этап 2 не требовал переделки.
2. **Бэкенд и синхронизация:** Worker + D1, `/register`, `/sync`, `/events`, `/blob`, `/ping`, вход со второго устройства (ПК), экран «Синхронизация», автозачёт, инструкция «Команд».
3. **Аналитика:** графики, адаптивная сложность, Тень на метриках, достижения, дерево навыков, магазин, недельные/босс‑задания.
4. **ИИ:** провайдеры, задания и корректировка от ИИ, недельный отчёт, генерация аватара по фото.
5. **Уведомления:** push‑подписка, cron.

После каждого этапа — инструкция «как открыть на iPhone и проверить». В конце — пошаговый деплой (GitHub Pages, Cloudflare), установка на iPhone, настройка «Команд».

## 15. Оставлено строителю

Точные тексты и банк заданий, названия классов/титулов/достижений, визуальные детали UI, библиотека Web Push для Workers, структура компонентов, количество шагов анкеты, точные коэффициенты (в пределах описанной логики).

## 16. Решения ассистента (проверь)

- Стек: React+Vite+TS, Dexie, GitHub Pages, Cloudflare Worker+KV.
- Синхронизация телефона и ПК через общий журнал событий в D1 (не «последняя запись побеждает»).
- Задания дня выдаёт первое открытое устройство.
- Токен генерирует приложение и регистрирует одноразово (`/register`).
- Формулы XP, Тени, адаптивной сложности и штрафов (раздел 9).
- 4 тира образа; Тень = фильтр поверх аватара.
- Gemini как рекомендуемый провайдер (текст + картинки, бесплатный лимит).
- Игровые сутки заканчиваются в **04:00**, а не в полночь (пользователь ложится поздно). К этой границе привязаны серии, штрафы, победа над Тенью и дата пакета. Время можно изменить в настройках.

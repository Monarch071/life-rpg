## 2. Архитектура

- Журнал событий — единственный источник правды; `replay(events, now)` чистая, не бросает, порядок входа не влияет. Новые события валидируются полями (граница доверия); неверное обязательное поле отбрасывает событие.
- Новые чистые модули без знания о журнале: `src/domain/ladder.ts`, `src/domain/shadow.ts` (имя свободно: старая ежедневная «Тень» удалена в Ядре), `src/domain/boss.ts` (боссы и цепочки), `src/domain/text.ts` (`cleanText`). Replay собирает входы по дням и вызывает их в существующем цикле по датам.
- **Монотонность** (Ядро §5, Автоматика §4.4): решение по закрытому дню (засчёт ритуала, срыв, сила грани, итог окна лестницы, битва, урон боссу) принимается по событиям, принятым до закрытия этого дня, и позже не меняется.
- Все числа — в `BALANCE` (§10). ИИ — только тексты и черновики (варианты босса, шаги цепочки и лестницы), всё проверяется валидаторами домена.

## 3. Лестницы привычек [S§7], [P§4]

### 3.1. Модель

```ts
interface LadderStep { label: string /* 1–60 */; per7: 1|2|3|4|5|6|7 /* 7 = каждый подходящий день */;
  auto?: { metric: AutoMetric; op: '>=' | '<='; value: number } }
type LadderKind = 'do' | 'dont'
```

Лестница — 5 ступеней (`steps.length === 5`). Пятая — «Автоматизм»: ритуал без срока.

| Ступень | Частота по умолчанию | XP за раз | Бонус за ступень |
|---|---|---|---|
| 1 Проба | 3/7 | 15 | 100 |
| 2 Закрепление | 5/7 | 20 | 150 |
| 3 Рост | 5/7, выше интенсивность | 25 | 200 |
| 4 Мастерство | каждый подходящий день | 30 | 300 + достижение «Мастер привычки» |
| 5 Автоматизм | как ступень 4, без срока | 10 | трофей-вещь аватару (§8.3), слот освобождается |

- Бонус ступени N начисляется при её **прохождении** (переход N → N+1). Переход 4 → 5 даёт и 300 XP, и трофей.
- «Подходящий день» — поле `suitable: 'all' | 'workdays'` лестницы; `workdays` — дни, чей тип `day` или `evening` (подъём «в первый час после подъёма» привязывается к моменту дня, а не к часу [P§4] — это текст ступени).

### 3.2. Откуда берутся

- **Предложения:** привычки профиля `goodHabits` (`sport`, `read`, `water`, `walk`, `meditate`) → готовые шаблоны лестниц по таблице примеров [S§7] в обобщённом виде; плюс «не делать»-шаблоны `social`, `sweets`, `late`. Шаблоны — в `ladder.ts` (`LADDER_PRESETS`), с авто-метриками там, где есть данные:

| Шаблон | Ступени 1–4 (5 = как 4) | auto |
|---|---|---|
| `read` Чтение | 10 стр 3/7 · 10 стр 5/7 · 20 стр 5/7 · 20 стр 7/7 | `readMin >= 15/15/30/30` (1,5 мин на страницу, Автоматика §4.4) |
| `sport` Тренировки | 20 мин 2/7 · 30 мин 3/7 · 45 мин 3/7 · 45 мин 4/7 | `workoutMin >= n` |
| `walk` Прогулка | 5 000 шагов 3/7 · 5 000 5/7 · 8 000 5/7 · 8 000 7/7 | `steps >= n` |
| `meditate` Медитация | 5 мин 3/7 · 5 мин 5/7 · 10 мин 5/7 · 10 мин 7/7 | `mindfulMin >= n` |
| `water` Вода | 1,5 л 3/7 · 1,5 л 5/7 · 2 л 5/7 · 2 л 7/7 | — (ручной ввод — честное слово) |
| `social` (не делать) Соцсети | до 2 ч 3/7 · до 2 ч 5/7 · до 1 ч 5/7 · до 1 ч 7/7 | `socialMin <= 120/120/60/60` (правила `<=` — Автоматика §4.4: только закрытый день, живой источник) |
| `sweets` (не делать) Сладкое | без сладкого после 18:00 3/7 · 5/7 · весь день 5/7 · 6/7 | — |
| `late` (не делать) Поздний отбой | лечь по шаблону дня 3/7 · 5/7 · 5/7 · 7/7 | — |

- **Своя привычка:** название + вид (`do`/`dont`) → `genericLadder(title, kind)`: частоты 3, 5, 5, 7, 7; ступень 3 с пометкой «(больше)».
- **ИИ** (если настроен ключ): для `do`-лестниц может построить 5 ступеней «от текущего уровня» [S§7]; ответ проходит `validLadderSteps`, при сбое — правила. Название `dont`-лестницы в ИИ не уходит (может совпадать с гранью Тени) **(моё решение)**.
- `dont`-лестница может ссылаться на грань (`facetId`): выполненный ритуал в этот день — ещё −1 к силе грани [S§7 «вторые одновременно ослабляют Врага-тень»] **(моё решение о величине)**.

### 3.3. События

```ts
| { type: 'ladder_created'; ladderId: string; title: string; kind: LadderKind; skill: SkillId; steps: LadderStep[];
    suitable?: 'all' | 'workdays'; facetId?: string }
| { type: 'ladder_updated'; ladderId: string; title?: string; steps?: LadderStep[] }   // «Мастер переформулирует»: действует со следующего окна
| { type: 'ladder_removed'; ladderId: string }
| { type: 'ritual_done'; ladderId: string; date: ISODate }                             // честное слово
```

Валидация: `title` — `cleanText(…, 40)`; `skill` ∈ каталогу; `steps` — ровно 5, `per7` целое 1–7, `label` 1–60, `auto.metric` ∈ `AutoMetric`; первый `ladder_created` с данным id побеждает. `ritual_done` принимается, только если `date === gd(ts)` (отметка за сегодня, до закрытия), лестница в этот день активна или на ступени 5, и один раз на лестницу в дату.

### 3.4. Окно, переходы, очередь

- **Окно** — 14 **незамороженных** дней. Замороженный день = день отдыха, день восстановления в лимите месяца или купленный «день без заданий» (Ядро §6.5, Автоматика §6) — окно на паузе [S§7 «пауза»]. Первое окно начинается с игровой даты `ladder_created`.
- **Засчёт дня:** `ritual_done` за дату, или авто — данные дня выполнили `auto` текущей ступени (та же функция, что у заданий: `>=` по максимуму незафлаженных, `<=` только закрытый день с живым источником). Авто поднимает честное слово до авто (влияет только на `verified`).
- **Нужно за окно:** `per7 < 7` → `2 × per7`; `per7 = 7` → число подходящих дней в окне.
- **Итог окна** (при закрытии 14-го незамороженного дня), `rate = min(1, сделано / нужно)` — `ladderAfterWindow`:
  - `rate ≥ 0,8` → следующая ступень, попытка 1, бонус ступени;
  - `0,5 ≤ rate < 0,8` и попытка 1 → та же ступень, попытка 2;
  - иначе (меньше 0,5 или второй провал) → ступень `max(1, N − 1)`, попытка 1, флаг `ask: true` — Мастер спрашивает «что мешает?» и предлагает переформулировать (лист с правкой ступеней → `ladder_updated`).
- **Рецидив ступени 5:** недели по 7 незамороженных дней; если выполнение меньше 60% нужного (частота ступени 4) **две недели подряд** — лестница возвращается на ступень 4 и занимает слот; слотов нет — становится **первой** в очереди.
- **Слоты:** активных (ступени 1–4) не больше 3. Новая лестница при занятых слотах — в очередь (порядок создания). Слот освобождается переходом на ступень 5 или удалением; первая в очереди становится активной со **следующего** дня (окно с этого дня).
- Ритуал ступени 5 показывается каждый день, но слот не занимает.

### 3.5. XP ритуалов

Ритуал даёт фиксированный XP ступени [S§1 «Ритуалы — фиксированные 10–30 XP»] — без множителя проверки, бонусов и штрафов **(моё решение: «фиксированные» читаю буквально)**. Строка леджера `source: 'ritual'`, 100% в навык лестницы и его характеристику, в уровень и сезон, золото 20%. Бонус ступени — строка `source: 'ladder'` в тот же навык. `verified` — авто-засчёт.

### 3.6. Серия [S§6]

`dayOutcome` получает `rituals: { due: number; done: number }` (`due` — лестницы, чей ритуал показан в этот день: активные + ступень 5). День засчитан, если он не отдыхающий и (`due > 0` и `done = due`) **или** выполнено ≥ 60% заданий. День без выданных заданий, но со всеми ритуалами — засчитан. Идеальный день — по-прежнему только по заданиям.

## 4. Враг-тень [S§7]

### 4.1. Грани

```ts
type FacetKind = 'games' | 'social' | 'late' | 'junk' | 'smoke' | 'procr' | 'alcohol' | 'custom'
| { type: 'facet_added'; facetId: string; name: string; kind: FacetKind; start: number /* 30–80 */ }
| { type: 'facet_removed'; facetId: string }            // убрать без изгнания (ошибся, неактуально)
| { type: 'shadow_relapse'; facetId: string; date: ISODate }
```

- Не больше 3 неизгнанных граней; четвёртая игнорируется. `name` — `cleanText(…, 40)`; `start` — целое 30–80, иначе событие отбрасывается.
- **Предложения из интервью** («которые ты сам назовёшь» — грань создаёт только пользователь): `profile.badHabits` (`games`, `social`, `late`, `junk`, `smoke`, `procr`, свои строки), ответы `smoking`, `alcohol`, `games_hours`, `screen_hours`, `time_leaks`. Ручное добавление — название + «как часто»: редко / иногда / часто / каждый день.
- **Стартовая сила** `facetStart` [S§7 «30–80, по частоте из интервью»] **(моё решение о шкале)**: редко 30, иногда 50, часто 65, каждый день 80. Из ответов: курение «Иногда» → 50, «Регулярно» → 80; алкоголь «Пару раз в месяц» → 30, «Раз в неделю» → 50, «Несколько раз в неделю» → 65; игры ч/день <1 → 30, <2 → 50, <4 → 65, иначе 80; телефон ч/день (для `social`) <2 → 30, <4 → 50, <6 → 65, иначе 80; без ответа — 50.

### 4.2. Сила — за каждый закрытый день

`facetDay({ strength, cleanRun }, relapse, assist)`:

- срыв в этот день → `+8`, `cleanRun = 0`;
- иначе `−2`, `cleanRun + 1`; каждый 7-й чистый день подряд — ещё `−5`;
- `assist` (выполнен ритуал связанной `dont`-лестницы) → ещё `−1`;
- результат в 0–100.

Пример (тест): старт 50, 6 чистых → 38; срыв → 46; 7 чистых → 46 − 14 − 5 = **27**.

- Грань считается с даты `facet_added` (первый закрытый день — день добавления). Сила тени = **среднее** по неизгнанным граням (округление), нет граней — `null`.
- Режим восстановления Тень **не** замораживает (документ замораживает серию, форму и лестницы) **(моё решение)**.

### 4.3. Срыв

- Источники [S§7 «чек-ин, кнопка или данные»]: кнопка в вечернем чек-ине (одна на грань), кнопка «Был срыв» на экране Тени, **данные** — для граней `social`/`games`: закрытый день, где минуты группы приложений > 120 при живом источнике (те же правила, что `<=`-задания, Автоматика §4.4) **(моё решение о пороге: 120 = «ноль баллов» соцсетей в Фокусе)**.
- `shadow_relapse` принимается, только если `date === gd(ts)`; срыв за вчера не ставится (монотонность). В день на грань — **один** срыв, сколько бы отметок ни было.
- **Честная отметка** (событие, не данные) даёт +5 XP в навык «Контроль привычек» (`habits`, Дисциплина) — строка `source: 'shadow'`, раз в день на грань. Срыв по данным XP не даёт. Игра поощряет честность и никогда не отнимает XP.

### 4.4. Усталость

`fatigueNext` получает `day.relapses` — число граней со срывом в день d−1 — и добавляет `+5` за каждую [S§3]. Новое поле `BALANCE.vitals.fatigue.relapse = 5`.

### 4.5. Битва — последнее воскресенье месяца

- Дата — `lastSunday(месяц)`: декабрь 2026 → 27-е, январь 2027 → 31-е, февраль 2027 → 28-е.
- При закрытии этого дня, если есть хоть одна неизгнанная грань, — итог по силе тени на конец дня:

| Сила | Итог | Награда |
|---|---|---|
| < 30 | сокрушительная победа | 400 XP + редкий трофей |
| 30–49 | победа | 250 XP |
| 50–69 | ничья | 50 XP + план Мастера на месяц |
| 70+ | тень сильнее | ничего; совет упростить лестницу |

- XP — строка `source: 'shadow'` в навык `habits` **(моё решение: куда идёт XP битвы)**. «План Мастера» — текст правил по самой сильной грани («Начни лестницу „не делать“ для …» или «Опусти лестницу на ступень»); ИИ не используется, потому что грани в ИИ не уходят.
- Битва, выпавшая на замороженный день, всё равно проходит (это итог месяца).
- **Анимация** — при первом открытии после даты битвы: лист «Битва с тенью» (~1,5 с: тень и герой сходятся, вспышка, итог). `prefers-reduced-motion` — сразу карточка итога без движения. «Показано» помнит `localStorage` (удобство одного устройства, `try/catch`).

### 4.6. Изгнание

Сила 0 и 30 чистых дней подряд → грань изгнана навсегда: достижение «Изгнание», слот свободен. Пример: старт 30 без срывов — на 30-й день (сила 0 с 13-го). Все грани изгнаны — тень исчезает с экрана, пока не добавишь новую.

### 4.7. Безопасность и приватность

- `isSerious(name, kind, answers)`: ключевые слова (алкоголь, наркотики, вещества, казино, ставки, азартные игры, самоповреждение) или алкоголь «Несколько раз в неделю». Такие грани **не предлагаются**; при ручном вводе показывается карточка: «Тень — для бытовых привычек. Если это зависимость, с которой трудно справиться самому, лучше обратиться к врачу или на горячую линию помощи — игра её не заменит». Кнопки «Понятно» и «Это бытовая привычка — добавить» **(моё решение: бережно предупредить, но не запрещать взрослому человеку)**. У такой грани нет анимации битвы — только сухая карточка итога.
- Названия граней не показываются на Главной (только «Тень 42»), не попадают в промпты ИИ (тест на `questContext`, `aiTuning`, `aiWeeklyReport`), в пуши и в ответ Worker. Уже существующая строка «вредные привычки: id из анкеты» в `questContext` остаётся — она под текущим согласием (владелец сам ввёл ключ); новые данные Тени в неё не добавляются.

### 4.8. Фигура тени

На экране «Герой» за аватаром — тёмный силуэт аватара (тот же SVG, `filter`/маска, цвет `--shadow`): масштаб `0,7 + 0,5 × сила/100`, непрозрачность `0,25 + 0,6 × сила/100`. Нет граней — нет силуэта. Подпись для чтения с экрана: «Враг-тень, сила 42».

## 5. Сезонный и месячные боссы [S§8], [S§6], [P§2]

### 5.1. Выбор

- В сезоне (не в Прологе) на вкладке «Задания» — карточка «Выбери босса сезона» с 3 вариантами и «Свой» [S§8]. Документ: «в первый день сезона»; этап выходит 9–15 декабря, поэтому выбор доступен **в любой день сезона** **(моё решение)**, части за прошедшие месяцы можно догнать (§5.3).
- **Правила** `bossOptionsByRules`: источники по порядку, без дублей — `profile.goals` (текст, характеристика) → активные легаси-боссы → ответ интервью `year_goal` → обобщённые цели темы сезона («Прочитать 3 книги» для «Разум и дух» и т. п.). До 3 вариантов. Части — общие: «Разведка» (разбить цель на шаги, первый шаг, выбрать мерило прогресса), «Наступление» (главный шаг месяца, проверить и поправить план, видимый результат), «Финальная битва» (последний рывок, закрыть хвосты, подвести итог). Навык — `DEFAULT_SKILL_BY_STAT[характеристика цели]`.
- **ИИ** (если настроен): `aiBossOptions(cfg, goals)` — те же цели, что уже уходят в `questContext`; ответ — 3 черновика `{ title, skill, parts: [{ title, steps[2–5] }×3] }`, каждый через `validBossDraft`; невалидный вариант заменяется вариантом правил.
- **Свой:** название, характеристика, по 2–5 шагов на каждую из 3 частей.

```ts
| { type: 'season_boss_set'; seasonId: string; boss: { title: string; skill: SkillId; parts: { title: string; steps: string[] }[] } }
| { type: 'season_boss_abandoned'; seasonId: string }
```

Валидация: `seasonId` — сезон игровой даты события (не Пролог); `title`, `parts[i].title` ≤ 60, шаг ≤ 80 (`cleanText`); ровно 3 части, в каждой 2–5 шагов. Принимается, если у сезона нет активного босса. После `season_boss_abandoned` можно выбрать снова; награда за победу — **одна на сезон** (ключ `seasonId`).

### 5.2. Части и урон

- Часть i ↔ i-й календарный месяц сезона. HP части 0–100:
  `HP = round(100 − 80 × шаговСделано / шагов − 4 × min(5, ударов))`.
  Пример: 1 из 3 шагов и 2 удара → **65**; все шаги без ударов → **20**; все шаги и 5 ударов → **0**.
- **Шаг** — задание дня `kind: 'boss'` (§5.3). Выполненное задание шага — следующий шаг.
- **Удар** [S§1 «урон боссу — прогресс, не XP»]: выполненное `daily`/`challenge`-задание с характеристикой босса в день, когда часть началась. Свои (`custom`), ритуалы и сами шаги ударами не считаются. Не больше 5 на часть.
- **Текущая часть для шагов** — самая ранняя начавшаяся (месяц наступил и босс выбран) с несделанными шагами; **для ударов** — самая ранняя начавшаяся с ударами < 5. Так недоделанная часть прошлого месяца догоняется первой.
- Статусы части: `upcoming` (месяц не наступил) · `active` · `late` (месяц прошёл, HP > 0) · `defeated` · `escaped` (сезон кончился, HP > 0).
- **Награды** **(моё решение о месячной)**: HP части дошло до 0 → +300 XP (`source: 'boss'`, 100% в характеристику босса, как у легаси); все 3 части побеждены до конца сезона → +1 500 XP и легендарный трофей [S§8], достижение «Покоритель сезона». XP шагов — обычная награда задания (одно действие не считается дважды [S§1]).

### 5.3. Шаг босса в дне и перенос

- `AssembleCtx.bossStep: { title; skill; link } | null` — первый несделанный шаг текущей части. Сборка ставит его сразу после обязательных заданий (у него P ≥ 3 по формуле [S§6] — терм «босс» равен 1), в счёт слотов и лимита «2 на характеристику». Ранг — потолок навыка босса, проверка — честное слово/фото.
- `Quest` += `link?: { kind: 'boss'; season: string; part: 0 | 1 | 2; step: number } | { kind: 'chain'; chainId: string; step: number }`; `QuestKind` += `'boss' | 'chain'`.
- **Перенос** [S§6 «связанное с боссом или цепочкой переносится»]: невыполненный шаг сгорает без штрафа и выдаётся снова на следующий день, пока не сделан.
- Не выдаётся: в день типа `rest`, в купленный «день без заданий», в режиме восстановления. Шаг не перебрасывается и не может прийти как своё задание.
- Replay: выполненное `boss`-задание продвигает шаг, только если его `link` совпадает с текущими частью и шагом на дату выдачи; иначе (дубль с другого устройства, мусор) это обычное задание — XP остаётся, урона нет.

### 5.4. Терм P

`bossStats` в `AssembleCtx` = характеристика текущей части сезонного босса ∪ характеристика активной цепочки ∪ характеристики активных легаси-боссов. Формула P не меняется.

### 5.5. Конец сезона

Сезонный босс принадлежит своему сезону: после `season.end` его части — `escaped` (кроме побеждённых), шаги больше не выдаются. Тема и босс сбрасываются [S§8 «сбрасывается: тема сезона и сезонный босс»].

### 5.7. Легаси-боссы v1

События `boss_created/boss_stage_done/boss_abandoned` работают как раньше (этап 100 XP, победа +200, Ядро §8). Создание новых легаси-боссов из интерфейса убирается; существующие показываются в разделе «Прежние цели» с кнопками «Этап выполнен» и «Сдаться». Их характеристика остаётся в `bossStats`, их названия — среди вариантов сезонного босса по правилам (можно «перевести» цель в сезонного босса; легаси-босс при этом не удаляется — пользователь сам сдаёт его кнопкой) **(моё решение: ничего не ломать в старом журнале)**.

## 6. Сюжетная цепочка [P§4], [S§6]

```ts
| { type: 'chain_started'; chainId: string; title: string; skill: SkillId; steps: string[] /* 3–6 */ }
| { type: 'chain_abandoned'; chainId: string }
```

- Одна активная: `chain_started` при активной — игнор. Шаги — из цели: ИИ `aiChainSteps(cfg, goal)` или правила `chainByRules(goal)` — «Собрать идеи», «Сделать пробу», «Получить первый результат», «Закрепить»; пользователь может править перед стартом.
- Шаг — задание `kind: 'chain'` с переносом, ставится после шага босса (оба — в одном дне, если хватает слотов), те же исключения, что §5.3.
- Все шаги сделаны → +200 XP (`source: 'chain'`, 100% в характеристику) и достижение «Сюжет завершён» **(моё решение о награде)**. Можно начать новую.
- `GameState.chain: { id; title; skill; stat; steps: { title; done }[]; current: number } | null`, `chainsDone: number`.

## 7. Сборка дня — изменения [S§6]

1. `AssembleCtx` += `bossStep`, `chainStep` (см. §5.3, §6); `bossStats` — по §5.4.
2. Порядок: обязательные (вернуть форму, ржавчина, Дух) → шаг босса → шаг цепочки → «каждая характеристика раз в 3 дня» → остальные по P.
3. **Шаблоны вредных привычек (`badHabit`) больше не кандидаты** — эти привычки живут в Тени и «не делать»-лестницах (Ядро §10). Шаблоны остаются в банке для легаси-карт.
4. Ритуалы — вне слотов [S§6], сборка их не выдаёт; они в `GameState.ladders`.
5. `rerollCandidate` для `boss`/`chain` → `null`; replay отклоняет переброс таких заданий.

## 8. Леджер, достижения, трофеи

### 8.1. Строки

`LedgerEntry.source` += `'ritual' | 'ladder' | 'shadow' | 'chain'` (боссы — существующий `'boss'`). Строки с навыком (`ritual`, `ladder`, `shadow`) — через `splitXp(xp, [skill])`; `boss`, `chain` — 100% в характеристику (`flatRow`). Все идут в уровень, сезон, золото 20%.

### 8.2. Достижения

Счётчики `laddersMastered`, `facetsBanished`, `shadowWins` (итог < 50), `chainsDone`, `seasonBosses`; `bossesDefeated` += побеждённые части. Новые: «Мастер привычки» (пройдена ступень 4), «Изгнание», «Тень отступила», «Сюжет завершён», «Покоритель сезона» (титул «Покоритель сезона»).

### 8.3. Трофеи

`GameState.trophies: { id: string; kind: 'avatar' | 'rare' | 'legendary'; title: string; date: ISODate }[]` — из ступени 5 лестницы, сокрушительной победы над тенью и сезонного босса. Названия — фиксированный список в `BALANCE.trophies`. Показываются на экране «Герой» полкой; надеть на аватар — этап 5 (инвентарь) **(моё решение: записать заслуженное сейчас, не строя инвентарь)**.

## 9. Интерфейс («стеклянная ночь»: токены `:root`, `lucide-react`, цели ≥ 44 px, `aria-*`, `prefers-reduced-motion`)

- **Главная:** над заданиями — полоса «Ритуалы»: по чипу на лестницу (название, «2/6 в окне», ступень), касание — `ritual_done`; авто-засчитанный — галочка «авто»; `<=`-ритуал — «засчитается при закрытии дня». Карточки `boss`/`chain` — бейдж «Босс»/«Сюжет», без кнопки переброса. Битва — лист §4.5. Тень на Главной — только число в плашке на экране «Герой», имён нет.
- **Чек-ин:** раздел «Ритуалы» (переключатели по невыполненным сегодня) и «Тень» (кнопка «Был срыв» на грань, подпись «Честно — +5 XP. Срыв — это данные, а не наказание»). Пишутся отдельными событиями при сохранении.
- **Задания (вкладка):** «Неделя» как сейчас → «Привычки» (активные с окном и ступенями 1–5, очередь, ступень 5; «Новая лестница» — предложения из профиля или своя, ИИ-кнопка «Построить ступени»; лист «Что мешает?» при `ask`) → «Босс сезона» (выбор из 3 + «Свой»; потом три карточки частей: HP-полоса `role="progressbar"`, шаги, статус; победа — празднование) → «Сюжет» (активная цепочка или «Начать из цели») → «Прежние цели» (легаси, если есть).
- **Герой (вкладка):** силуэт тени за аватаром §4.8; панель «Враг-тень»: грани с полосами силы и «чисто N дн.», «Был срыв», «Добавить грань» (предложения, частота, карточка безопасности), «Убрать», дата следующей битвы, итог прошлой; полка трофеев.

## 11. Мои решения (заполненные пробелы)

1. Золото и магазин не трогаются — готовы с «Ядра»; критерий «первая покупка» — ручная проверка.
2. Ритуал — фиксированный XP ступени, без проверки/бонусов/штрафов.
3. Бонус ступени — при её прохождении; 4 → 5 даёт 300 XP и трофей.
4. Окно — 14 незамороженных дней; заморозка = отдых, восстановление в лимите, «день без заданий».
5. «Подходящий день» — `all` или `workdays` (типы `day`/`evening`).
6. Очередь — по порядку создания; активация со следующего дня.
7. Шкала стартовой силы грани 30/50/65/80 и соответствие ответам анкеты §4.1.
8. Срыв — один на грань в день; только за сегодня; честная отметка +5 XP, данные — без XP; порог данных 120 минут.
9. Тень в режиме восстановления не замирает.
10. Выполненный ритуал `dont`-лестницы — ещё −1 к связанной грани.
11. XP битвы — в навык «Контроль привычек»; «план Мастера» — правила, без ИИ.
12. Серьёзная зависимость: не предлагается, при ручном вводе — карточка с советом обратиться к специалисту и подтверждение; без анимации.
13. Названия граней — только в журнале владельца; не в ИИ, не на Главной, не в пушах.
14. Босс сезона выбирается в любой день сезона; недоделанные части догоняются до конца сезона.
15. HP части = 100 − 80 × доля шагов − 4 × удары (≤ 5); удар — `daily`/`challenge` с характеристикой босса.
16. Месячный босс +300 XP; сезонный +1 500 XP и легендарный трофей один раз на сезон.
17. Шаги босса и цепочки — задания дня с переносом, сразу после обязательных; не в отдых, «день без заданий», восстановление.
18. Цепочка завершена → +200 XP.
19. Шаблоны `badHabit` уходят из сборки.
20. Легаси-боссы доживают как «Прежние цели»; создание новых убрано.
21. Трофеи — записи без инвентаря до этапа 5.
22. Анимация битвы «показана» — `localStorage` одного устройства.
